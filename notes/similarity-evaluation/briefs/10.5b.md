## Why (so that you can judge the small things)

Step 10.5d adds a background worker of `pangloss-reconcile` that, after a save, puts a suggestion in the place
of an unreconciled mention. Whether a save sets it off is a project setting, **and a parameter of the one write
overrides it either way** (`?suggest=false` from a pipeline that identifies for itself; `?suggest=true` where
the setting is off). `suggest=false` must also take off a mark left by an earlier save. The core must know
nothing of `suggest` nor of reconcile: it gains one general thing, an app declares its instruction, and reads
what the write said where pending work is marked.

What the `Explore` found, which shapes the design:

- A function of `hooks.pending_work` is given only the class, and `pending.mark_written` is called by deletes,
  undeletes, merges and their undoing, review status changes, relinks, computed writes and derived conversions
  as well as creates and updates. An instruction must count **only in a create or an update of a head**.
- Review's `?review_status=` is a middleware by path: it applies to every POST and PUT under `/api/` (other
  apps' routes too), and background tasks copy its context. **Do not build it that way.** The API refuses an
  unknown query parameter by the dependency `known_parameters`, and a route may be marked
  `@checks_own_parameters` and call `refuse_unknown_parameters(request, also=...)`: the model write routes
  take the declared instructions that way, and only they.
- Nothing can take a mark off in a write's transaction today (`complete` needs a claim's token).

## What to build

### 1. Declaring and saying an instruction (`pangloss_models.hooks`)

- A frozen dataclass `WriteInstruction`: `name: str` (snake_case; the API takes camelCase too, as for every
  parameter), `values: tuple[str, ...]` (what it may say, as text: `("true", "false")`), `description: str`.
- `write_instructions: dict[str, WriteInstruction]` and `declare_write_instruction(instruction)`: a name
  declared twice with another definition raises `PanglossModelError` (the same definition again is fine: tests
  run modules again); a name that is a parameter the model write routes already have (`detail`, `created_by`,
  `toolchain`, `toolchain_version`, `toolchain_date`, `acknowledge_citations`, `published`, `review_status`,
  `review_assigned_to`) is refused the same way.
- `checked_instructions(said: Mapping[str, Any] | None) -> dict[str, str]`: `None` gives `{}`; a `bool` is
  taken as `"true"`/`"false"`; an undeclared name or a value not among the declared raises a typed error that
  names what is declared (a `PanglossWriteError` subclass if that family fits a refused argument of a write:
  look at what it holds and choose; say which). Over the API both are a 422 in the API's usual shape.
- **Where a write's instructions count.** A new hook beside `pending_work`:

      type InstructedWorkFor = Callable[[type, Mapping[str, str]], Mapping[str, bool]]
      instructed_work: list[InstructedWorkFor] = []

  Each function is given the class of the head and the instructions of the write (**an empty mapping when the
  write said none**) and answers, by kind of work, `True` (leave a mark) or `False` (**take a standing mark of
  that kind off**, in the write's transaction); a kind it does not name is left as it is. It is asked **only by
  a create and an update of a head** (and for the entities a create makes with it, by their class, with the
  same instructions): never by a delete, an undelete, a merge or its undoing, a relink, a change of review
  status or of publication, a computed write, a derived conversion, a restore's bookkeeping other than its own
  update (a restore is an ordinary update and says no instructions). The comment over it says all of that in
  the manner of the others, and that an app whose work depends on what a write said uses this **instead of**
  `pending_work` for that kind.
- How the instructions get from `save` to the marking is yours to choose (an argument passed down to
  `_write_new_head` and from `update_head_node` to `replace_head_in`, or a context variable set by exactly
  those entry points), on one condition, which has a test: **nothing that copies a context can make another
  caller count them** (a merge, a delete or a background task started from inside a write, e.g. by an
  `after_write` listener, must see no instructions; each create and update sets its own, empty if it said
  none). If a context variable, it is private to the core; apps read instructions only as the argument of their
  `instructed_work` function.

### 2. The database (`pangloss_cypher`)

- `pending.unmark(tx, kind, head_ids)`: the marks of the kind for those heads deleted, claimed or not (a
  worker that holds a claim then completes nothing: check `complete` and the workers' handling of a claim whose
  mark went, and say what you found).
- `mark_written` (or a function beside it called from the two places): after the kinds of `pending_work`, the
  `instructed_work` answers are applied, `True` as a mark (with `before` kept if the kind is in
  `pending_keeps_before`, as for the others; `less` respected), `False` by `unmark`. With no function in
  `instructed_work`, **no statement more** (the budgets of `test_query_costs.py` unchanged with no app
  declaring).
- `create_head_node`, `checked_create` (it writes nothing: it only checks the instructions),
  `create_heads`, `update_head_node`, and `save_with_companions` gain `instructions: Mapping[str, Any] | None
  = None`, checked by `checked_instructions` **before anything is written**.

### 3. From Python, the stubs, the SDK, the API

- `X.Create(...).save(instructions={"suggest": False})`, `X.Update(...).save(instructions=...)`,
  `create_heads(..., instructions=...)`, `save_with_companions(..., instructions=...)`. `typestubs.py`'s
  `save_methods` gains the argument (`Mapping[str, str | bool] | None = None`).
- The SDK (`protocol.create`, `create_with_companions`, `update`, both the async and the sync
  `exposed_functions`): the instructions are carried as query parameters of the request (the declared name, the
  value as text). The SDK does not have the server's declarations necessarily (it has the models' code, so
  `hooks.write_instructions` is filled only if the app that declares is importable there): it sends what it is
  given and lets the server refuse. Say what you found about that.
- The API (`routes/models.py`): `create_item`, the with-companions route and `update_item` are marked
  `@checks_own_parameters`, call `refuse_unknown_parameters(request, also=declared names)`, read the declared
  instructions from the query (after `QueryNames`, so snake_case), and pass them to the save. An undeclared
  parameter is still the 422 it is today (a test, with no instruction declared and with one). **No other
  route** takes them. If it is cheap, the declared instructions appear in the OpenAPI document as query
  parameters of those routes (look at how `openapi.py` is made); if not, say so and leave it.
- Review's `RequestedStatus` middleware stays as it is (not this step's).

### 4. One helper for "this document written again with this part replaced"

`pangloss_review.reconcile.rewrite_part` and criteria's `resolving.resolve` / `sharing.share` each read a head,
dump it `editable`, replace nodes in the tree, validate `Model.Update(**data)` and save with the version read;
the worker of 10.5d would be a third copy, and needs the same **without saving** (a trial: would this place take
this replacement). In the core (`pangloss_models`: a module of its own, e.g. `rewriting.py`; its public names
from the package root if the neighbours' are):

- the pure tree functions, once: `replaced_where(value, chosen, replace) -> (value, found)` and
  `replaced(value, id, replace)` (criteria's is the more general: move it, with whatever it gained in 11.3 to
  say which ids it replaced);
- `async def prepare_rewrite(model, head_id, change) -> Prepared | None`: reads the head (as criteria's
  `read_view` does: `get_for_edit` for an entity, `get` for a document; check that review's tests hold with
  it), applies `change(data) -> (data, found)` to `editable(view.model_dump())`, and gives `None` if the head
  is gone or nothing was found (two cases the callers tell apart today? then make them distinguishable: look at
  the errors each raises), else `Prepared(view, update, version)` with `update = model.Update(**data)` made,
  **a pydantic `ValidationError` let through** for the caller to turn into its own error;
- `async def rewrite(model, head_id, change, *, version=None, **save_options)`: `prepare_rewrite`, then
  `update.save(expected_version=version or the version read, **save_options)` (so a caller can pass
  `instructions=`), giving the `Prepared`.
- `rewrite_part`, `resolve` and `share` use it and **keep their behaviour exactly**: their errors, what they
  return, the version rules (`resolve` takes a caller's version), `tell_resolved` where it is.
  `pangloss_reconcile/stored.py` mirrors the `Update` construction for planning without writing: look, and use
  `prepare_rewrite` there only if it is a plain fit; otherwise leave it and say so. Merge and relink build the
  same `Update` for other ends: leave them.

## Tests

- **Pure** (`packages/pangloss-models/tests/`, new files; basenames unique across all packages):
  `declare_write_instruction` (twice the same, twice differing, a reserved name), `checked_instructions` (none,
  a bool, an unknown name, an unknown value, each message); the tree functions (as criteria's and review's
  tests have them: move or keep those tests where they make sense); the stubs show the argument.
- **Conformance, both backends** (you run Neo4j; `packages/pangloss-testing/src/pangloss_testing/conformance/`,
  a new file, with an instruction and an `instructed_work` function declared by the test in a `try`/`finally`,
  as `test_citations_basis.py` does with `hooks.notices`; a kind of the test's own):
  - marked or not by the instruction, on create and on update, from Python; with no instruction said the
    function is still asked (an empty mapping) and its answer applied (the "setting" case);
  - `False` takes off a mark that an earlier write left, in the same transaction as the write (a write that is
    refused, e.g. a stale version, leaves the mark);
  - an entity made with a create is asked for by its class;
  - **none of the other callers asks**: delete, undelete, merge and undo, a review status change and
    set-published, a restore's update says none (asked with an empty mapping, as any update), a computed write
    if a fixture for one is near; and a merge and a delete run **inside a context copied from within a
    create that said an instruction** count nothing;
  - an unknown name and an unknown value refused before anything is written (node and mark counts before and
    after);
  - `create_heads` and `save_with_companions` carry them to each head;
  - `test_query_costs.py`'s budgets hold unchanged with nothing declared (run it).
- **API** (`packages/pangloss-api/tests/`, where the write routes' tests are): each of the three routes takes a
  declared instruction (camelCase and snake_case) and it reaches the function; an undeclared parameter is a
  422, a bad value a 422; a route that is not one of the three refuses it as unknown.
- **SDK**: a contract test where the SDK's others are (find how `protocol.update`'s `If-Match` or
  `acknowledge_citations` is tested against a server) that create, update and with-companions send them.
- **The helper**: review's and criteria's existing tests **unchanged and green** (run
  `packages/pangloss-review`'s and `packages/pangloss-criteria`'s live tests and the conformance files
  `test_reconcile_live.py`, `test_identify_live.py` on Neo4j; say the counts); a few direct tests of
  `prepare_rewrite` (head gone, nothing found, invalid replacement raises `ValidationError`, nothing written by
  it: counts before and after) and `rewrite` (version given, version moved on is refused, `instructions`
  passed through).
