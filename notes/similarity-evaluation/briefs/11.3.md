## Why (so that you can judge the small things)

Step 11.4 (not yours) makes `pangloss-reconcile` keep which candidate a person took, in a listener of this event,
which **writes to the database**. The existing write listeners (`after_write`) are synchronous and may not write,
and they cannot tell a reconciliation from any other update. So: a new, general event of the core, with no
package's name in it, raised by the packages that have a route of their own for putting an entity in a stand-in's
place.

## What to build

1. **The core, `pangloss_models.hooks`** (beside `Notice`/`notices`/`give_notice`):
   - a frozen dataclass `Resolution`: `stand_in_id: UUID`, `stand_in_type: str` (the class of the stand-in's node:
     `Unreconciled`, or the `MatchesCriteria[...]` use's type as its node says it), `head_id: UUID`,
     `head_type: str`, `entity_id: UUID`, `entity_type: str`, `user: str`, `at: datetime.datetime`, `direct: bool`,
     `label: str | None = None`, `stood_for: str | None = None` (the value of the property `StandIn.named_type`
     names, if the stand-in has one);
   - `resolved: list[Callable[[Resolution], Awaitable[None]]] = []`;
   - `async def tell_resolved(resolution: Resolution) -> None`: awaits each listener in turn; one that raises is
     logged with `logger.exception` (saying the stand-in's id and head) and the others are still told; never
     raises itself. With no listener it does nothing (and logs nothing above debug).
   - The comment over it, in the manner of the others, says: who raises it (a package that has its own route for
     putting an entity in a stand-in's place), **when** (after the write of the document has returned, outside any
     transaction, so a listener may write; a write that failed raises nothing), that it is awaited (a slow
     listener slows the request: keep it to one small write), what `direct` means (the one the person had open,
     against one resolved along with it), and **what it is not**: an edit of a form that replaces a stand-in, a
     restore from history, an update through the SDK or by a toolchain raise nothing. A listener must not rely on
     hearing of every stand-in that goes.
   If the names clash with something in `hooks.py` you find, choose near ones and say so.
2. **`pangloss_review.reconcile`**:
   - `reconcile`: after `_reconcile_one` has returned for the mention asked about, `tell_resolved` with
     `direct=True`. **Never when `in_form=True`** for that mention (nothing is written to its document).
   - each `also` mention written in the background (`reconcile_other` in `reconcile`, including those in other
     documents when `in_form=True`, which are written), and each of `reconcile_with`'s: `direct=False`, after its
     `_reconcile_one` has returned.
   - The event is made of what is already read (`row`: id, head, label, `unreconciled_type`; the entity's id and
     class; the user of the request, as the write itself knows them; now): **no query more** to make it. If the
     row lacks something the event wants, say so in the report rather than add a query; the label may then be
     None.
   - Whether the event comes before or after `give_uris`: after the document's write and before `give_uris` (a
     failure of the URIs must not lose the event). Say if the code makes that awkward.
3. **`pangloss_criteria.resolving.resolve`**: after `update.save` has returned, one event for **each place**
   replaced (`same_one` puts the entity in several): the place asked about (`id`) `direct=True`, the others
   `direct=False`; `label=None`; `stood_for=None`. `replaced_where` may need to say which ids it replaced: change
   it as little as will do (its other callers keep working).
4. **Tests.**
   - Pure, `packages/pangloss-models/tests/` (a new file; basenames are unique across all packages):
     `tell_resolved` with no listener; two listeners both told, in order; the first raising, the second still
     told, the failure logged (`caplog`), nothing raised.
   - Conformance (both backends), beside `test_reconcile_live.py`/`test_identify_live.py` in
     `packages/pangloss-testing/src/pangloss_testing/conformance/` (a new file, or added to
     `test_reconcile_live.py`, as fits; listeners appended in a `try`/`finally` as
     `test_citations_basis.py` does with `hooks.notices`): one event for a reconciliation with **every field
     asserted**; one for each `also` mention, `direct` false (wait with `reconcile.background_done()`); none for
     the mention with `in_form=True`, but one (`direct` false) for an `also` mention of another document then;
     `reconcile_with` (through `identify`'s confirming, or called directly) gives `direct` false; a reconciliation
     that fails (no such entity; a class that cannot take the place) gives none; a listener that raises does not
     fail the reconciliation, the document is written, and it is logged; a listener may itself write to the
     database (make one that runs a small write query through the backend, and assert it is there).
   - Criteria, where its live tests of `resolve` are: one event for a single place (`direct` true); for a
