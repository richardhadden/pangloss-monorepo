# 10.5b report (builder): choices as they were made

## Choices

1. **How the instructions reach the marking: an argument, not a context variable.** `create_head_node`,
   `create_heads`, `update_head_node` check them first (`hooks.checked_instructions`) and pass the checked dict
   down: `write_head_node` / `write_head_nodes` -> `_write_new_head`, `replace_head_node` -> `replace_head_in` ->
   `pending.mark_written(..., instructions=)`. `instructions=None` at `mark_written` means "not a create or an
   update of a head": `instructed_work` is not asked (every other caller: delete, undelete, merge and undo,
   relink, review status, computed, derived conversion). `{}` means "a create or update that said none": asked
   with an empty mapping. Nothing is in a context, so nothing that copies a context can carry them.
2. **The error**: `PanglossInstructionError(PanglossWriteError)`, in `pangloss_models.exceptions`, for both an
   undeclared name and a value not declared (a refused argument of a write, nothing written; the family's
   handler gives it the API's usual `{detail, error}` shape, and the SDK raises it again by name). 422 in
   `STATUS_FOR_ERROR`. Over the API an undeclared *parameter* is still refused by `refuse_unknown_parameters`
   (the `unknown_parameter` 422 of today), since the routes pass only the declared names as `also`.
3. **A class change** (`changing_class_from`): `instructed_work` is asked for the new class only; the second
   `mark_written` for the class it was gets no instructions (one head, one answer per kind; two answers could
   disagree).
4. **`keeps_before`** also asks `instructed_work` (with the write's instructions), so a kind an app answers
   `True` that is in `pending_keeps_before` gets `before` as a `pending_work` kind does.
5. **Several apps answering one kind**: the later function in `instructed_work` wins.
6. **The API passes `instructions=` to `save` / `create_heads` only when the request said one** (`instructed()` in
   `routes/models.py`). The same in meaning (a save given none is asked with `{}`), and the existing API tests that
   stub `save(self, detail=False)` keep working.
7. **Value errors over the API come from the save** (`PanglossInstructionError`, 422 `{detail, error}`), not from
   the route: the route takes the declared names off the query (`refuse_unknown_parameters(also=declared)`) and
   leaves the checking to the one place that checks. The OpenAPI document has the declared instructions as
   parameters of the three routes (`openapi_extra`, which FastAPI 0.150 appends to the route's own parameters): cheap,
   done. Declared after the app is made, an instruction is still taken (it is read at request time) but is not in the
   OpenAPI document.
8. **`save_with_companions`** checks the instructions itself first (before `_to_db_model` and the companions are
   made) and passes them to `create_heads`, which checks them again (cheap; it is also a public entry).
9. **The rewrite helper**: `pangloss_models/rewriting.py`; `prepare_rewrite` and `rewrite` from the package root,
   the rest (`replaced_where`, `replaced`, `read_head`, `Prepared`, `Missing`) from the module (`replaced` is too
   general a name for the root). The two "nothing" cases are told apart: share skips a head where nothing is found
   any more but reports one that is gone; so `prepare_rewrite` gives `Missing("head")` or `Missing("part")` instead
   of `None`. Both functions take `read=` (what reads the head): `share`'s test monkeypatches `sharing.read_view`
   (left in place as a wrapper of `rewriting.read_head`), and `rewrite_part` needs the view for the words of its
   `PanglossReconcileError` when the `Update` does not validate (`prepare_rewrite` lets the `ValidationError` through,
   so the caller has no view otherwise). Criteria's `replaced`/`replaced_where` and review's `replaced` stay
   importable from their modules (re-exported), so `test_meta_and_status.py` is unchanged.
10. **`rewrite_part` and `resolve` now read an entity head with `get_for_edit`** (as `share` did); before they used
   `get` for every head. A document head is read with `get` as before.
11. **`pangloss_reconcile/stored.py` left as it is**: it changes nothing in the head (it plans the stored `Update`
   whole), so `change -> (data, found)` and `Missing("part")` do not fit it plainly; 10.5d's trial is the place that
   will use `prepare_rewrite`.
12. **Stubs**: `save_methods` gains `instructions: _pg_typing.Mapping[str, str | bool] | None = None` (every `save`).
   The framework stubs have no `save` (`framework_stubs --check` exits 0 after the change): not made again. The
   demo's stubs do have `save`, and are out of date until `pangloss make-stubs` runs in `pangloss-demo/` (not mine).
13. **Docs**: there is no one page of the hooks; the two sections went into `implementation_docs/packages.md`
   (under pangloss-models: "The instructions of one write ✅", "A head written again with a part replaced ✅"),
   a paragraph in `api.md` (by "Query parameters"), a bullet in `sdk.md`.
14. **A function of `instructed_work` may be asked twice for one write**: seen in the full Neo4j run (the restore's
   update was asked twice: its transaction ran again under load). Said in the hook's comment (answer the same, read
   and write nothing); the conformance tests compare the questions asked once each (`distinct`).

## Found

- `pending.complete` of a claim whose mark was taken off deletes nothing and gives 0; the workers (vectors, derived,
  criteria, review's URIs) ignore the count, and `release` of a missing mark matches nothing. So a worker that held
  a claim of a mark a write took off finishes its batch, writes what it computed and completes nothing: harmless
  for those kinds; 10.5d's worker should check the mark is still there (or that `complete` gave 1) before it writes.
- `test_query_costs.py::test_each_read_is_one_transaction_of_the_statements_it_has_always_had` fails on Neo4j when
  run in one process after `test_reconcile_live.py` or `test_identify_live.py` (a document read takes 2
  transactions, 6 statements), and passes alone; the same at HEAD (run from a `git archive` copy of HEAD's
  `packages/`): an order dependence that is not this step's.
- The SDK's `protocol.create_with_companions` sends neither `published`/`review_status` nor `review_assigned_to`
  of `**options` (only `created_by`/`toolchain`, and now `instructions`): not this step's.
