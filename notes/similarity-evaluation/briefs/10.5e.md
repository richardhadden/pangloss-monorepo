## What to build

1. **One function** `suggesting.mark_stored(classes: Sequence[str] | None = None, again: bool = False) -> Marked`:
   in pages (a database of a million nodes: no one transaction over everything; measure nothing, but write it
   so that it is one indexed read and one write for each page), the heads that (a) are of a class that can hold
   a stand-in (10.5d's rule; `classes` narrows it, with their subclasses; a name that is no such class is
   refused with the names that are), (b) **hold a stand-in now** (a node of a class of `hooks.stand_ins` below
   them or the head itself: find the cheapest query on both backends, by the stand-in classes' labels and
   `head_node_id`), (c) are not deleted and are unpublished (the worker would leave a published one anyway:
   do not mark what will be left), and (d) **have no mark of the kind already** (row 23: marking again takes a
   claim off). `again=True` first forgets what was tried (`forget_tried`, for those heads' stand-ins) so that
   stand-ins left before are asked again. Gives how many heads were marked, how many already had a mark, how
   many stand-ins they hold. After the marks are committed the worker is woken (`hooks.emit_work_marked` or as
   the vectors' rebuild wakes its worker: find it).
2. `POST /api/reconcile/suggest` (**admin only**; body `{"classes": [...], "again": false}`, both optional;
   answers the counts; a 403 for a user who is not an admin, as the other admin routes are refused).
3. The admin job `reconcile_suggest` (as `reconcile_learn`: its parameters if jobs take them, else all classes
   and `again` false; say which) and, if the page has a place for it as the vectors' Rebuild has, **no new
   interface** unless the job list shows jobs by itself (look; if a button needs writing, stop and say so: it
   is then 10.5g's).
4. `pangloss reconcile suggest [--class NAME ...] [--again]` and `pangloss reconcile status` (how many heads
   wait, how many are claimed, how many stand-ins were tried and left, how many suggestions the worker wrote
   that are not yet confirmed (`PGReconcileSuggested`), whether it waits for the vectors, who holds the lease;
   also the answer of `GET /api/reconcile/suggest` for an admin, the same figures).
5. Docs: `implementation_docs/reconcile.md`, `guide/cli.md` (the commands; its test of the commands listed),
   `guide/vectors/reconcile.md` (a short section: turning it on, the instruction for a pipeline
   `?suggest=false`, after a bulk load `pangloss reconcile suggest`), `implementation_docs/api.md` if routes of
   apps are listed, `status.md`, the skill's row (+ `check_skill.py`). Not `similarity-build-plan.md`, not
   `TODO.md`.

## Tests (live, both backends; new files with unique basenames)

- `mark_stored`: marks the heads with a stand-in and no others (a document without one, a published one, a
  deleted one, a class that cannot hold one, a derived document); a head already marked is not marked again
  (its token unchanged, a claim kept); twice in a row marks once; `classes` narrows, with subclasses; an unknown
  class refused; `again` clears what was tried so that the worker asks again (count `candidates_of`), and
  without it a tried stand-in's head is marked but its stand-in skipped; paging (a page size of 2 in the test);
- the route: admin, not admin (403), not logged in (401); the counts; `GET`;
- the job run through the admin package's own test pattern;
- the commands (the CLI's test pattern: output and exit code), and the CLI guide's test;
- after a bulk load (the backend's `bulk_ingest` wrapper or the nearest fixture: documents written with
  `suggest=false`): no mark; then `mark_stored` marks them and a drain suggests.
- Then `ruff format --check packages`, `ruff check --select F,B packages`, `ty check`.
