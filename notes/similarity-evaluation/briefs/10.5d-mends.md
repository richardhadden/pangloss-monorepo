1. **A publish between the worker's read and its write lands the suggestion on a published document** (the
   only check is on the view read once; `set_review_status` does not change `meta.version`, so the update's
   version check passes). **And 2. a `suggest=false` save of a head already claimed in the batch is ignored**
   (nothing looks at whether the mark of the claimed token still exists; the worker reads the new version and
   writes). **Mend both in the update's own transaction**: `update_head_node` takes `before_write=` (find what
   it is given; if it cannot read the head's properties and the mark there, use the place the kept rows are
   written, `hooks.in_write`, **provided a raise there rolls the whole write back**: check, with a test): the
   head is still unpublished, **and the mark of this head with the claimed token is still there**. Either
   failing: nothing written (the transaction rolled back), and: published → as a published head is treated at
   the first check (its mark completed if it is still this claim's, logged); the mark gone or of another token
   → the head dropped without completing anything (another save or trigger owns the mark now). With the token
   checked in the transaction, a mark made again meanwhile (finding 7: the trigger with `--again`) is no
   longer taken off by the worker's update: for that, **`mark_stored(again=True)` marks the heads that already
   have a mark too** (a new token: that is the point of `again`), and the worker's update must not delete a
   mark of another token: it says `instructions={"suggest": False}` today, which unmarks **by key**; keep the
   instruction (it stops the update marking anew) only if the unmark it causes cannot remove a newer mark
   inside this transaction (it cannot be newer inside the transaction once the token is checked first and the
   mark node is locked by that read/write: reason it through for both backends and say so), else complete by
   token there and find another way not to mark.
3. **Marks are completed with no work done while the profile is `pending` or `rebuild_due`** (a stand-in whose
   candidates are not `ok` is skipped, then the head's mark is completed or unmarked: after the rebuild nothing
   is marked). **Mend**: a batch is not claimed while the profile reconcile searches by is not `ok` (read its
   state where the rebuild's lease is read; `pending_status` says "waiting for the vectors: the profile is
   …"); and if a stand-in still comes back not `ok` inside a batch (the state changed under it), the head's
   mark is **kept** (the claim given back) and nothing of that head is written or noted.
4. **One head that raises something that is not a refusal starves everything younger, for ever** (its claim is
   given back, the batch shrinks to one, the oldest is claimed alone every turn). **Mend**: the worker counts
   the failures of a head (in its process; a restart starts again); at the third, the head is treated as a
   refusal is (logged at error with the exception, its mark completed, its stand-ins **not** noted as tried),
   and the batch goes on with the others. Also `stored.plan_of_view`: a `PanglossWriteError` that is not a
   `PanglossWriteRefused` is `Unplannable` too, if that is right for every subclass (look).
5. **Any refusal of the update notes every stand-in of the head as tried, including those just decided.**
   **Mend**: a refusal notes as tried only the stand-ins that were left undecided for a reason of their own
   (no place for a suggestion; decided "nothing"); those decided and not written are not noted.
6. **Nothing records that a person rejected a suggestion**: a restore of the version before the worker's
   update brings the stand-in back with its old id, the save marks the head (with the setting on), and the
   worker writes the same suggestion again. **Mend**: when the worker replaces a stand-in it also notes it as
   tried (its digest as it was), in the same transaction: restored, it is skipped until its digest changes or
   `--again`. (A suggestion edited back to a mention by hand is a new node with a new id and is asked again:
   left, and said in `reconcile.md`.) The sweep must not remove a tried row whose stand-in is gone **while a
   `PGReconcileSuggested` or an example made of it still names it**; say what rule you gave it.
7. **The digest of "tried" holds nothing of the place**: a stand-in whose place takes no suggestion, moved to a
   field that takes one, is still skipped. **Mend**: the digest includes where the stand-in sits (the path of
   field names from the head) and the shape found (or "none").
8. **An entity head of a class that can be marked** is left only because `getattr(view.meta, "published", True)`
   defaults to True. **Mend**: say it outright (an entity is not a document a person reviews: the worker
   leaves entity heads, mark completed, logged), and `marking` does not mark entity classes at all if that is
   simpler; a test.
9. **Context inherited by tasks started during the worker's write** (`marking.keeping`, the toolchain's
