## What to build

1. **Two classes in `pangloss_library.models`**, exported from the package root and in its `__all__`:
   - `IdentificationFromText[T](Identification[T])`: `text: str`, what the source wrote (the name as it stands
     there). A person may make one by hand, so `text` is an ordinary field of its form.
   - `IdentificationByToolchainFromText[T](IdentificationByToolchain[T])`: `text: str`,
     `confirmed_as = IdentificationFromText`; `text` hidden on forms as its other toolchain fields are
     (`hide_on_forms`), and shown in the form not to be changed exactly as the library's interface module shows
     those (find how it does `identified_by`/`uris` and follow it; a `t()` slot with translations if a caption
     is needed). Its label index as `IdentificationByToolchain` has (`_meta`: check whether a subclass inherits
     `label_index=True` and what `suggestion_labels`/the migrations expect; every class of suggestion needs its
     own label index).
   - Docstrings in the manner of the others, and the module's docstring says the two.
2. **`check_confirmed_classes`** also refuses (each a `PanglossModelError` that names the class, the field, and
   the fix; if errors here carry a `fix=` for the language server, as the skill says a new refusal should, give
   one):
   - a confirmed class with a field that has **no default** and that the suggestion's class lacks (a
     confirmation keeps only the fields the two have in common, so it could never be written);
   - a field that the two classes **type differently** (compare the annotations as declared; a field of the
     suggestion that the confirmed class lacks is fine, it is "of the suggestion only");
   - and, **as a `PanglossModelWarning`, not a refusal** (main's call, from the plan's "a warning, not a
     refusal, for a project's existing fields"): a relation field that takes a class of suggestion and not the
     class it becomes (a field that says only `IdentificationByToolchain[Person]` takes the suggestion and
     could not take it confirmed). This one needs the fields analysed: if `before_finalise` is too early for
     it, find the right moment (there may be an after-initialise hook; say what you used). One warning for each
     field, naming the model, the field, the suggestion class and the class to add.
   What is excluded from the comparison: `NOT_KEPT` of review (`type`, `id`, `identified_by`, `target`,
   `toolchain_version`, `uris`). The library does not import review: say the list once in the library and, if
   it is natural, let review read it from there when the library is installed; otherwise leave review's alone
   and say so.
3. **Migrations.** `pangloss-library`: the next migration (two `CreateModel`s, the label index of
