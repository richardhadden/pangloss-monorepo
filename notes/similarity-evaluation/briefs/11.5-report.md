# Step 11.5: the builder's report (kept as it went)

## Choices made where the brief left room

1. **The module that does the work is `fits.py`, not `models.py`**: an installed app's `models.py` is imported by
   the CLI and the API as the app's model declarations (`pangloss_cli.project`, `pangloss_api.app`), so the name is
   taken. `pangloss_reconcile.fits`: `learn(dry_run=False) -> Learnt`, `use(id | None)`, `Learnt.lines()` (the
   printed lines, shared by the command and the admin job's report). `learning.py` is the pure part.
2. **What "today's" is, in one function**: `decisions.today(states)` gives the five stored properties (`profile`,
   `signature`, `parts`, `weights` as JSON text, `features`); the writer of 11.4 (`record_of`) now stores exactly that,
   and the retraining and `--use` compare an example's or a fit's five with it, as equal values.
   **This changes 11.4's `parts`**: it was the signatures of the parts in the rows' scores (so an unknown that had no
   vector of a part had a smaller `parts`, and would have been counted "of other vectors" instead of "lacking a
   part"); it is now the signature of every part the weights weigh above 0 (but `shared`) that has a state. For the
   tests' and the demo's `who` (name and graph) the two are the same. A profile never built has no signature today:
   no example is today's then.
3. **A decision's "rows lacking a part"** is told by `learning.lacking(rows, ranking_features)`: a feature missing from
   any row's `scores`. An example with no rows lacks nothing; it goes into the ranking model with no row and is left
   out of the "none of these" model as "no row displayed".
4. **The feature parts** are the parts `settings.weights()` weighs above 0 (but `shared`), by name, then `shared` if it
   weighs: the same list both models and `today()` use.
5. **`head_features(rows)`** names `best_X` for every key of the best displayed row's `scores` (so it needs no list of
   features, as 11.6 calls it on a live answer); the rows displayed are ordered by `score`, highest first, ties as
   given (a stable sort): the rows are kept in the hand-set order already.
6. **"Decisions" of a fit** is the count after both filters (what the ranking model is fitted on); the decisions with
   no row displayed are counted (`undisplayed`) and left out of the "none of these" model only. The check's
   `RECONCILE_LEARN_FROM` is against that count.
7. **No decision at all** (none left after the filters): nothing is fitted and nothing written ("Nothing fitted and
   nothing written: there is no decision to learn from"). One decision or more: a fit is written, whatever the
   models (`Unfittable` gives null with why).
8. **"Nothing new"** is checked against the newest fit **of today's signatures** (`of_today`), comparing `decisions` and
   `latest` (datetimes made UTC before comparing). Done in a dry run too.
9. **A comparison that cannot be made** (`compare`/`compare_calls` raising `Unfittable`, e.g. fewer decisions than
   folds) leaves that model's `compared` null; its why is printed, not stored (the brief's node has no place for it).
   For the "none of these" model this fails the check ("could not be compared").
10. **The check's message** lists every condition that failed, joined by "; " (fewer than `RECONCILE_LEARN_FROM`; not
    fitted; not compared; worse than the commoner, with the two numbers). `fits.why_not` is the one function, used by
    `learn` and by `use` (on the stored `decisions`, `none`, `none_why` and `compared["none"]`).
11. **A fit not put in use** prints which fit stays in use ("The fit in use stays in use: ID", or "No fit is in use:
    suggestions are ranked by the score set by hand").
12. **`--use` and `--dry-run` together** are refused (a usage error). `--use` of an unknown id: "Refused: There is no
    fit ID", exit code 1; every refusal is printed as "Refused: …" with exit code 1. `--use none` is case-blind.
13. **The dry run's sweep** is counted by `decisions.sweepable()` (the sweep's own condition, as a read returning
    `count`): cheap, so it says how many would be removed.
14. **Writing a fit**: one write transaction that unsets every `in_use: true` (only when the new one is in use) and
    `CREATE`s the node; `use` unsets and sets in one write transaction. Null properties are left unset by both backends
    (reading gives null).
15. **The migration** `0002_models.py` (named for the node, as the brief names no file name) makes an index of
    `PGReconcileModel(id)` beside the unique constraint, as 11.4 did for the example (Memgraph's constraints make no
    index). `dependencies = [["pangloss_reconcile", "0001_initial"]]`, as `pangloss-dates`' second migration has.
16. **The admin job**: options `Choice("dry_run", ("no", "yes"), "no")`; counts `swept`, `read`, `other`, `lacking`,
    `decisions`, `undisplayed` (`Learnt.counts()`); the report file is `learnt.txt`. Translations added to the app's
    `translations/ui.jsonc` for its title, option, values and counts (en, de, fr), as `pangloss-rdf`'s job has.
17. **`RECONCILE_LEARN_FROM`** is refused by `_whole` like the other whole-number settings ("a whole number of 1 or
    more (the fewest decisions a fit is made of for it to be put in use), not …"). The live conftest gives it (100),
    and the tests set it to 40 (`monkeypatch` on the settings object) so the live tests write tens of examples, not
    hundreds.
18. **The live tests' examples** are written through `decisions.write_example` (factored out of `heard`, which now
    calls it), with `decisions.today()` of vector states the test writes itself (`PGVectorState` for `name` and
    `graph`, `PGVectorProfile` for `who`, made-up signatures): no model declared, no vector built.
19. **The "worse" case** draws, for lists that all look alike, whether the best or none was taken at random (p 0.5).
    With the seed 3 the "none of these" model calls fewer rightly than the commoner answer; the test asserts that it
    does (it is seeded: the same each run), not that every such draw would.
20. **The CLI tests are a file of their own** (`test_reconcile_learn_command_live.py`, not async: the command runs
    its own loop), importing the generator from `test_reconcile_learn_live.py`, as the sweep command's test is a file
    of its own.

## Mends after the second reading

1. **The threshold counts the "none of these" model's decisions.** `fits.why_not(none_decisions, …)`. In `learn` it
   is given `len(none_examples)`. In `use` it is given the stored model's `examples`, or 0 when the model is null.
   The reason reads: `its "none of these" model is of N decisions, fewer than RECONCILE_LEARN_FROM (M)`. The node's
   `decisions` is unchanged, since the "nothing new" shortcut uses it.
   - Test: `test_the_threshold_counts_the_decisions_of_the_none_model_not_every_decision`. It has 80 decisions, 20 of
     them with nothing displayed, and puts the threshold between the two counts. `learn` keeps the fit out of use and
     `use` refuses it. At the "none" count, `use` puts the fit in use.
   - The earlier tests now expect the new text. A fit whose "none" model is null is "of 0 decisions" in `use`.
2. **`least` is a sixth value of `decisions.SIGNATURES`.** It is `settings.least_score()`, a number. It is written
   on a shown record (`KEEP_QUERY`), on an example (`write_example`) and on a fit (`fits.PROPERTIES` takes
   `SIGNATURES`). `of_today` compares it. There is no migration.
   - `use`'s refusal text now names `RECONCILE_LEAST_SCORE` among what may have changed.
   - Test: `test_examples_of_another_least_score_are_left_out_and_a_fit_of_one_is_refused`.
   - `test_reconcile_decisions_live.py` now expects `least` on both nodes and checks it against the setting.
   - `reconcile.md` names `limit` as a known limit in one sentence.
3. **The comparison's reason is stored.** `ranking_why` / `none_why` hold why the model was not fitted, or, when it
   was fitted but not compared, why the comparison could not be made. `why_not` no longer has the literal
   "too few decisions".
   - Test: `test_use_of_a_fit_whose_comparison_could_not_be_made_is_refused_with_why`. Nine decisions took a
     displayed row and one took none, so the fold holding the one "yes" leaves "All 8 examples are no". `use`
     refuses with exactly that reason.
4. **The printed lines.**
   - (a) The ranking line ends `(recorded: nothing uses the ranking model)` (`fits.RANKING_UNUSED`).
   - (b) The line is now `No fit is in use` (`fits.NO_FIT`), in `fits.py` and `cli.py`. I also removed "suggestions
     ranked by the score set by hand again" from `use`'s docstring.
   - (c) "Nothing new…", when that fit is not in use, adds `; it is not in use (`pangloss reconcile learn --use ID`
     puts it in use, through the check)`.
   - Tests: (a) in `test_enough_decisions…` and in the new ranking test; (c) in
     `test_nothing_new_since_a_fit_not_in_use_says_how_to_put_it_in_use`.
5. **Tests.**

     assert against it, not against `learnt.undisplayed`.
   - `test_reconcile_learn_command_live.py` applies migrations 0001 and 0002 in an autouse fixture, in a loop of its
     own (`run_connected`), and expects `No fit is in use`.
   - New `made(by_hand=True)`: in lists of someone offered, every name is high, the graph is spread from 0 to 1, and
