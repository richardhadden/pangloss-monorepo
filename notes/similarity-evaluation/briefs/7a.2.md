## The step (from the plan)

`GET /api/NAME/{id}/similar` takes `id: UUID`. For an entity class it is to take what `GET /api/NAME/{id}` takes: the
UUID, or one of the entity's URLs. The route becomes `/{model_name}/{ref:path}/similar`, parsed by
`pangloss_api.routes.models.parse_reference`, with the route's own query parameters (`profile`, `type`, `limit`, and
`field`, which step 7a.4 will add: leave it out of the URL's query now) not taken as part of the URL's query string.
`views.visible_item` resolves the reference with `pangloss_cypher.lookup.resolve_id` in the read transaction it
already has. A document is found by its UUID only, as at its own route.

## What main found, by reading (check the first by running before you build on it)

1. Starlette's `path` converter is `.*` and greedy, and the app's router is included before the models'. So
   `/api/Person/http://x.org/a/similar` should be matched by the similar route with `ref = "http://x.org/a"`, before
   the model's `/{ref:path}`. **Confirm this with a request first.** If it is not matched first, stop and report.
2. A consequence: an entity whose own URL ends in `/similar` can no longer be read at `GET /api/NAME/{that URL}`
   (the similar route takes the request, and looks for the URL without `/similar`). Its similar is at
   `…/similar/similar`, which works because the match is greedy. Decided for this step: this is accepted and
   **said**: the 404 of the similar route, when the reference is a URL that no entity has, says in its `detail` that
   an entity whose URL itself ends in `/similar` is read by its id. Test both halves (below). Do not try to fall
   through to the model's route.
3. `entity_reference` filters a fixed set `OWN_PARAMETERS`. The similar route needs the same with its own set. Make
   the smallest general change in `pangloss-api` that lets a route say its own parameters (for instance a function
   `reference_from(request, ref, own)` that `entity_reference` then calls), not a copy of the parsing in
   `pangloss-vectors`.

## What to build

- `api.py`: the path `/{model_name}/{ref:path}/similar`; the reference parsed as above; a URL at a document class is
  a 422 that says a document is found by its id; the 404's text follows `not_found` (id or URL). The `operation_id`
  stays `vectors_similar`. The module docstring's description of the route brought up to date.
- `views.py`: `visible_item(model, reference, see_unpublished)` takes `UUID | AnyHttpUrl`, resolves it with
  `resolve_id` inside the read transaction it has, then goes on as now (the label check, the survivor of a merged
  entity, what the reader may see). A URL of an entity merged into another answers for its survivor: read
  `resolve_id` to see what it gives for a merged entity's URL, and make the route right whichever it is.
- Nothing in the interface: it asks by UUID.
