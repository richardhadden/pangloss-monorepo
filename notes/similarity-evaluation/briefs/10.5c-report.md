# 10.5c report (builder): the decision's settings, and an unconfirmed suggestion is not evidence

Written as the choices are made; the final summary is at the end.

## Choices

1. **`decide_for` is in `suggest.py`**, beside `decide`: `percentages` and `decide` stay pure; `decide_for` reads
   the settings (imported inside it) and is the one function that does. One module for the decision is easier to
   find than two; the docstring says which is which.
2. **`fit` of `decide_for` is the "none of these" `pangloss_learn.Model` of the fit in use, or None**: the caller
   (the stored route, the worker of 10.5d) has already read `fits.in_use()` and decided `fits.usable(fit, today)`;
   `decide_for` does not read the database. "Probably new" is one function for both, `learning.probably_new(model,
   answered, above)` (the likelihood and whether it is above), which `api.none_of_these` now calls too.
3. **The dialog's limit is `candidates.DISPLAYED = 5`**, beside `KEPT`; `decide_for` cuts the list it is given to
   it. The interface keeps its own `LIMIT = 5` (`interface/src/api.ts`), held equal by a test that reads the file;
   `test_reconcile_learning_planted.py` imports the constant in place of its own `DISPLAYED = 5`.
4. **Settings**: `suggest_above()`, `suggest_most()`, `suggest_within()` in `settings.py`, in `__all__` and
   `check()`; a number from 0 to 1 is refused by one helper (`_share`), the most by `_whole` as the others.
   `RECONCILE_SUGGEST_MOST` above `DISPLAYED` (5) is allowed (the brief says 1 to 10) and keeps at most five.
5. **The hook**: `hooks.unconfirmed` / `hooks.unconfirmed_classes()`, beside `references_not_counted`. The library
   registers `models.suggestion_classes` (the registry's classes as declared that descend from
   `IdentificationByToolchain`, as review's `suggestion_labels` finds them), once (`_registered_once`).
6. **fastrp**: a wrapper class the hook names is `END` (nothing of its own kept, as `stop=True`); a name of a class
   that is not a wrapper (a document, an entity) or of no class changes nothing in the maps. The library's classes are
   `END` in every project that has the library (they are registered whether or not a field takes them), so **every
   such project's graph signature changes once**: `pangloss vectors status` says "rebuild due: its signature is now
   ..., not the ... it was built with" for the part `graph` and the profiles that weigh it (live test).
7. **The test models**: `similar_models.declare(suggested=True)` (default off, so nothing else changes):
   `Activity.participants` also takes `Identification[WeightedAlternative[Person]]` and
   `IdentificationByToolchain[WeightedAlternative[Person]]`, beside an `InRole` and inside one. `parts.writes` has
   `suggestion`, `in_role`, `suggestions`, `gathering`, `suggesting`, `participants_added` and `confirmed` (by
   `pangloss_models.rewriting.rewrite`, every part keeping its id); the suite of the parts has one test more, run by
   every part's suite (graph, class, name, time).
8. **`reasons.py`, the shape chosen**: for each of the two edges (`e1` into the candidate, `e2` into an entity of the
   payload), after the existing conditions, `AND (n.head_node_id IS NULL OR NOT EXISTS { MATCH (n)<walk>(n_held)
   WHERE any(label IN labels(n_held) WHERE label IN [...]) })`, the walk being `Dialect.through_wrappers(...,
   backwards=True)`: up the forward edges into the node, through wrappers only, none too (Memgraph: `<-[* 0.. (e, to
   | NOT e.reverse AND to is a wrapper)]-`; Neo4j: a quantified path `((a)<-[e]-(b) WHERE ...)*`). The same walk is
   already used inside `EXISTS` by the search compiler (`search_query.py`, `via`), on both backends. With no class
   named the text is exactly the old one (checked against `git show HEAD`'s `_query`, and by a pure test that it has
   no `EXISTS`).
   - **Why through wrappers and not `up_reverse`** (the reverse edges, which `node_allowed` in search uses): from a
     nested node the reverse edges lead up to the head and then **past it** (an entity head's reverse edges go to
     every document that names it; a document head's to a `DerivedFrom` if any), which would find another document's
     suggestion and be wrong as well as slow. The forward edges into a nested node come only from its parent, and the
     walk stops at the first node that is not a wrapper (a nested document, the head).
   - **The guard `head_node_id IS NULL`**: a head (a head document, an entity with a relation of its own to the
     candidate) is below nothing; and from an entity the walk would follow every wrapper in every document that
     names it. Whether each planner short-circuits the `OR` before the `EXISTS` is **not measured** (main at size).
   - **Shapes considered and not taken**: (a) a plain variable-length match with `all(...)` over the path: Memgraph
     does not prune by it, the walk would expand every edge; (b) the walk with a node condition `to.head_node_id =
     n.head_node_id` in the lambda/QPP instead of the guard (no `OR`; prunes an entity at the first step), not taken
     because it needs a new `Dialect` method or argument and I did not check Neo4j accepts an outer variable in a
     quantified path's predicate: **the one to try if the `OR` is not short-circuited at size**; (c) finding the
     suggestions of the heads involved first (`MATCH (s:IdentificationByToolchain {head_node_id: hid})`): no index
     on `head_node_id`, a scan of the label per head; (d) a mark written on the nodes below a suggestion at write time:
     a storage change, out of the brief.
   - **A document below a suggestion is not climbed through**: its own edges count (as the graph part joins a
     nested document's own entities to it). An `Embedded` is not a wrapper of `WRAPPER_LABELS`, so a chain
     suggestion → embedded → wrapper → node would not be found from the node (none of the library's classes holds
     one).
9. **The plan asked about is cut too** (`reasons.guessed`, used by `named_entities`): what the document asked about
   suggests itself (a second mention's document holding the worker's first suggestion) is not among its entities, by
   the same rule (through wrappers; an entity written in it is its own head). The brief named only the stored
   documents' edges; without this, a document's own unconfirmed suggestion of A would lift every candidate named with
   A elsewhere, a path by which an unconfirmed suggestion changes a later score (the ★ question). Live test: a
   payload with a suggestion of Cy, then the same as an `Identification`.
10. **What is not changed**: what "uses" an entity (`fragments.uses_of`, the check before a delete, typology's
    groups) still counts a suggestion; the name part (entities only) and the time part need nothing (a suggestion
    holds no date of its own in the library); the class part is by class.
