## What main decided (build these as said)

### 1. A general hook in `pangloss-vectors`: what a part keeps with a generation

The name part's refresh needs the table of rarity that its last rebuild made. A part does not know its generation
and the switch comes after `rebuild` returns, so `pangloss-vectors` gains a small general thing (no word of names
in it):

- **A part may have a method `kept(self) -> str | None`**: text that the rebuild just finished worked out over
  every item and that its refresh and overlay need. Optional: asked with `getattr`, not added to what `Part`
  requires (the class and graph parts have none; `register_part` must still take them). Document it in `parts.py`
  beside the protocol.
- `rebuild._rebuild_parts`, after `await rebuilt.rebuild(write)`, asks it and, if it gives text, stores it with the
  new generation **before the switch**: `store.keep(part_name, generation, text)` writes
  `(:PGVectorKept {part, generation, text})` (`MERGE` on part and generation: safe to run again).
- `store.kept(part_name) -> str | None`: the text of the generation **in use** of the part (by its state), None if
  there is none. Also `store.kept_in(tx, part_name, found: States)` for a caller already in a transaction, if you
  need it.
- `store.drop_older(part, keep)` also deletes the part's `PGVectorKept` below `keep`; a rebuild that stopped
  before its switch leaves one that the next rebuild's drop removes (check: `next_generation` must not hand out
  that number again. It looks at `PGVector` and `PGProfileVector` only: a part that wrote a kept text and no
  vectors is the case to think through and say in the report).
- An index `PGVectorKept(part)` in `structure.INDEXES` and a new migration `0003_vector_kept.py` as `0002` is
  written (Memgraph scans every node for a label without an index). The tests' helpers that make the indexes
  (`vectors_live_support`, `fastrp_live_support`, `pangloss_testing/parts`) get it through `structure.INDEXES` if
  they already read that list; check.
- Live tests in `packages/pangloss-vectors/tests/live/test_vectors_kept_live.py` (both backends), with a made-up
  part registered for the test: a rebuild stores the text and `store.kept` gives it only after the switch; a second
  rebuild replaces it and the older is gone; a part with no `kept` stores nothing; a rebuild that fails after
  `rebuild` returned and before the switch leaves the text in use as it was.
- `implementation_docs/vectors.md`: where it describes a part, say this.

### 2. `pangloss_names/meta.py`: which classes have names, and which fields

`_names_meta = NamesMeta(fields=["label"], include=True)`, a meta slot as `FastRPMeta` is (inherited by
subclasses, a subclass's own overriding). Defaults with no slot: **an entity** has names, its `label`; **a
document** has none (`include=False`) unless its class says `include=True`. `fields` are fields of the class that
are text: `str`, `str | None`, or `list[str]` (each item a name); anything else, or a field the class has not, is
refused at `initialise()` with a `PanglossModelError`-style message naming the class and field (see how
`pangloss_fastrp.meta` refuses, and give `fix=` if the neighbours do). A class that `pangloss-vectors` gives no
vectors (`pangloss_vectors.meta.included`) has no name vector either.
`meta.named() -> dict[str, list[str]]`: concrete class name → its name fields, for every class that has names.

### 3. `pangloss_names/part.py`: the part `"name"`

`name = "name"`, `local = True`, `weight = 0.0` (so it is in no profile until a project's `VECTORS_PROFILES` weighs
it), `requires` as the class part's.

- `dimension()`: `settings.dimension()`, `NAMES_DIMENSION`, default **256**, a whole number from 8 to 2048,
  checked as `FASTRP_DIMENSION` is.
- `signature()`: `signature_of(meta.named(), dimension, <hash of the table of variants>)` and nothing else (the
  rarity table is what a rebuild makes, not what it depends on).
- `rebuild(write)`: read every name in pages (the page query below), keep them in memory (an id, a type and a few
  words each); `maths.Rarity.of(...)` over the items a reader could be shown; then `maths.vector(names, rarity,
  dimension, table)` for each and `write` in pages; the table as JSON (`{"names": n, "having": {...}}`, sorted
  keys) is what `kept()` then gives. An item whose names give no vector (`None`) has none.
- `refresh(changed, write)`: if the part has no kept table in use (never rebuilt), write nothing. Otherwise the
  heads written and the documents nested in them (as the class part's refresh finds them, only if some document
  class has names), read by the items query below, their vectors by the **kept** table, written with `write`. A
  written item that now has no vector (its names emptied, or it is no longer one a reader could be shown): look at
  how the graph part's `refresh_ids` deletes the vectors of stops that have none
  (`store.remove_vectors`) and do the same. **`Refreshed(written=n, stale=n)`**: every name vector a refresh
  writes is weighed by a table that does not count it, which is what "left out of date" means in
  `VECTORS_REBUILD_AFTER`'s words; say so in the docstring.
- The kept table is parsed once for a generation and remembered in the process (it can be megabytes): the part
  keeps `(generation, Rarity)` and reads again when the state's generation is another. Forgotten on
  `ModelRegistry.on_reset` as the class part forgets its maps.
- `overlay(plan)`: for the plan's head (`plan.head`: `type`, `id`, `properties`), if its class has names, the
  vector of its name fields' values by the kept table; `{}` otherwise, and `{}` if there is no table yet.

### 4. The queries (tried on 630,000 nodes: 40,644 names in 0.5 s on Memgraph; both start from the index of `PGIndexableNode(id)`)

Take them from `class_part._page_query` and `_items_query` (same `fragments` for the head, deleted and merged, so
they hold on both backends), with two changes: the item filter is `n.type IN $types` (the classes of
`meta.named()`), and each row also carries `[f IN $fields | n[f]]` where `$fields` is the union of the name fields
(a class that lacks one gets null for it; drop nulls, flatten lists). If two classes name different fields, a field
one class has and does not name must not be read as its name: filter by class in Python from `meta.named()`.
The exact text tried is in `notes/similarity-evaluation/names_query_trial.py`.
