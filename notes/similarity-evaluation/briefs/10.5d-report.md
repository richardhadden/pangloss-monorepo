# 10.5d report (builder): the worker that suggests, choices as they were made

Written as the work goes; the summary is at the end.

## Choices

1. **"People write it"** (row 25): a class of head that has an `Update`, is not abstract, and that
   `hooks.written_by_people` says people write (so not a derived document, nor a class an app says it alone
   writes). Not the create route's filter (`create_directly`): a head that can be updated and not created is one.
   "Can hold a stand-in": some relation field of it, at any depth (through nested documents, reified relations,
   conjunctions, semantic spaces; never into an entity, nor a citation), has an option that is a document of
   `hooks.stand_ins`. Worked out once after `initialise()` (`ModelRegistry.after_finalise`), kept as a set of class
   names that the function of `hooks.instructed_work` reads.
2. **The claims**: `pangloss_cypher.pending` gains two general things, used by nothing else yet: `claim(...,
   before=)` (only marks made before that time: what waiting for the vectors needs, so that a batch never claims a
   mark whose write has not reached the vectors), with its own query text so the other workers' text is unchanged;
   and `renew(tx, kind, claimed, lease)` (a claim still held, by token, is given more time: what renewing while it
   works needs). Both are small and of the module's own data; doing them in reconcile would have copied the key
   format and the label.
3. **Where the code is**: `marking.py` (point 1: `KIND`, the instruction `suggest`, the function of
   `hooks.instructed_work`, what can be marked, and the function of `hooks.in_write`; nothing of the database
   imported, as `_install` wants) and `suggesting.py` (the worker; `suggest.py` stays pure). `stored.py` gains
   `plan_of_view(model, view)`, the plan of a head already read, which `stored_plan` now ends with.
4. **The settings**: `RECONCILE_SUGGEST_ON_SAVE`, `RECONCILE_SUGGEST_AS`, `RECONCILE_TOOLCHAIN`,
   `RECONCILE_WORKER_IN_SERVER`, in `settings.py` and `check()`. `RECONCILE_TOOLCHAIN` is checked to be a username
   (the users' own pattern). `RECONCILE_SUGGEST_AS` is checked to be a name always, and to be a model with the five
   fields (`check_suggest_as`) at `initialise()` only when the setting on save is True, and by the worker **only when
   it has claimed something** (`ready()`, with the toolchain): so a project with nothing marked (the server's worker
   runs in every project with the app) is asked nothing, and no toolchain user is made in it.
5. **The digest of a stand-in tried** holds, beside today's signatures (`decisions.today`) and the settings of the
   decision (`RECONCILE_SUGGEST_ABOVE`/`_MOST`/`_WITHIN`, `RECONCILE_NEW_ABOVE`, the fit in use when it is used,
   `RECONCILE_SUGGEST_AS`, `DISPLAYED`), **the stand-in's own label, class and URIs**: a person who edits a mention
   (its id kept) has it asked again. Beyond the brief's two; without it "until something that would change the
   answer has changed" would not hold for an edit.
6. **The rows kept, and the stand-ins tried, are written in the update's own transaction** through `hooks.in_write`
   (a function that does nothing unless a context variable, set by the worker around its one save, names the head
   being written: so no other write, nor a context copied from inside it into another write of another head, can
   write them; `MERGE`d by id, so a transaction run again writes them once). A crash cannot leave a suggestion without
   its rows, nor rows without a suggestion. Where nothing is written (nothing decided, a refusal), the stand-ins tried
   are written in the transaction that completes the mark.
7. **Waiting for the vectors**: the claim takes only marks made before the oldest mark of the vectors' kind, the
   oldest first (`pending.claim(before=)`); a rebuild holding its lease claims nothing. The rebuild's lock is not
   taken (the worker only reads vectors; a rebuild that starts during a batch switches generations atomically). With
   no vectors app installed nothing is waited for.
8. **Few heads, renewed**: `Settings.batch` 5 (`--batch` of the command), the worker's lease and the batch's claims
   renewed every quarter of the lease (30 s) while it works.
9. **The cited check** is a read (`citations.citing`, what cites the head, from documents not deleted, **published
   or not**: the user's word was "does not change a part that something cites", so an unpublished citing document
   counts too, though the update's own check would only mark its citation) before any candidate is asked. A
   stand-in is in a cited part when the citation is of it, of a node above it, or of the head; or of any node of a
   head whose class cites with every part the field the stand-in is in (`cited_with`). The update's refusal
   (`PanglossCitedError`) stays behind it as any refusal.
10. **What is not a refusal** of the update: `PanglossReadOnlyError` (a migration), `PanglossUserNotFoundError` and
    `PanglossUserDisabledError` (the toolchain gone or disabled since `ready()`): the claims given back and the error
    raised, as for any failure. Every other `PanglossWriteError`, and a `ValidationError` of the whole update, is a
    refusal.
11. **A stand-in whose candidates are not `ok`** (the profile not built, a rebuild due): left, not noted as tried
    (its mark completed): the answer would change once built. Logged at info.
12. **The command** `pangloss reconcile worker [--batch N]` gains `--once` (what can be done now, how many, and
    stop): the brief asks for a test of the command once, and a command that runs until stopped cannot be tested so.
    A refused toolchain is said and exits 1.
13. **`toolchain_version`**: `"profile who"`, or `"profile who, fit <id>"` when a fit in use was used (usable today)
    in the decision. `identified_by` is the toolchain's username. The toolchain is made with the full name
    "Pangloss's reconciliation".
14. **The label after the rewrite** (point 11), found on the test's `Gift` (`label_template="{given_by} gave to
    {given_to}"`): a head whose template names the field read the stand-in's label ("Ada gave to Jon Smith"), and after
    the rewrite read the suggestion's target, the candidates' labels joined ("Ada gave to Jon Smyth"): the machine's
    guess in the head's label. **Decided: the head keeps the name the source wrote**, by giving the library's
    `IdentificationByToolchainFromText` a label template `"{text}"` (`ReifiedRelation.Meta(label_index=True,
    label_template="{text}")`): a reified relation's template is how it reads in the label of what holds it (it has
    no label of its own, `require_label` is always False). Small, in the library, no migration (templates are not in
    the snapshot), the interface reads the same template from the export. Confirmed, it is an
    `IdentificationFromText`, which has none and reads as who was identified: the label then changes, when a person
    has said who it is. A project's subclass inherits the template. Seen to work on Memgraph before the tests were
    written.
15. **A conflict is retried in the same drain**: the claim given back is claimed again at the next turn of the
    drain (the person's own vectors mark is newer than the reconcile mark, so nothing waits): one drain then does the
    head twice, the first writing nothing. The test says so (`drained() == 2`, one update, version 3).
16. **The guide** (`guide/vectors/reconcile.md`, its settings): the four settings of the worker, under a line that
    says it is being built. The three settings of 10.5c are not in the guide's table (they were not before): left.
17. **`pyproject.toml` not changed**: the tests import `pangloss_history` (as derived's tests do without listing it);
    adding it to the dev group would have changed `uv.lock`.
