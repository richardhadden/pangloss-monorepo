## What to build

1. **A listener of `hooks.confirmed`** (installed with the app, beside `decisions.heard`), which does one small
   write: for a confirmation whose suggestion has a `PGReconcileSuggested` (the worker wrote it; an outside
   toolchain's has none and makes nothing):
   - **the confirmed target is of exactly one entity** → a `PGReconcileExample` for it with
     `via: "suggestion"`, `taken` that entity **if it is among the rows the worker kept**, else none (the
     person chose someone the worker did not offer: "none of those offered", rightly), the rows and
     `displayed` as the worker kept them, the comparable record (`today`) as kept **at the time of the
     suggestion**, the user and time of the confirmation; and the `PGReconcileSuggested` removed, in the same
     transaction;
   - **several entities still** (confirmed as it is with alternatives open) → no example; the kept rows **stay**
     (main's call, differing from the plan's row, which removed them: a person may collapse it to one later, by
     another confirmation or a form's save, and that is then a decision; say if the code makes this wrong, e.g.
     if the node is no longer found as a suggestion and no second event can come);
   - `direct` is recorded on the example and **not** required (the user: a form's edit that puts someone else
     in the place of a suggestion counts too);
   - `RECONCILE_KEEP_DECISIONS = False` → nothing written (and the worker of 10.5d keeps no rows then: check,
     and mend there if it does).
   What identifies the example: examples are one for each stand-in today (`PGReconcileExample` by stand-in id);
   a suggestion has a new id, not the stand-in's (row 11). Use the suggestion's id as the example's key and say
   so in `structure.py`'s comment; check nothing assumes the key is a stand-in's node.
2. **The sweep** (`decisions`' "undone" rule, row 1): an example whose stand-in is a node of a document again is
   removed today; an example `via: "suggestion"` is **left** (a confirmed suggestion keeps its node id: it is
   always "a node of a document"). Instead such an example is undone when its node **is a suggestion again**
   (restored from history to before the confirmation) or is gone: look at what the sweep can ask cheaply, and
   build that if it is one query; else leave them and say so. `PGReconcileSuggested` whose suggestion is
   neither a suggestion node nor confirmed (gone) are removed (10.5d built this: check it holds with examples).
3. **`learn`** (`fits.py`, `learning.py`): examples `via: "suggestion"` are read with the others, **counted
   apart** in what `learn` prints and in the `PGReconcileModel` record (how many of the decisions came from
   suggestions), and left out when `RECONCILE_LEARN_FROM_SUGGESTIONS` is False (a new setting, True, checked at
   `initialise()`, in `settings.py`'s docstring). They count towards `RECONCILE_LEARN_FROM` when in.
   **Nothing the worker wrote reaches `learn` without a person's act**: `PGReconcileSuggested` is never read by
   `learn`; assert it in a test (suggestions written, none confirmed, `learn` sees no decision).
4. Docs: `implementation_docs/reconcile.md` (learning: the two ways an example is made, what is not one),
