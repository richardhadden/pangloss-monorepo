## What it is for (so that you can judge the small things)

Step 11.5 (not yours) fits two models from the examples kept here: a ranking model (one example for each row
kept, "yes" the row taken) and a "none of these" model (one example for each decision, "yes" when none of the
rows **displayed** was taken). So an example must hold exactly what was offered when the person decided, with
the numbers the score was made of, and must be made only of a decision that reached the database, by the person
the list was shown to.

## What to build

1. **The ten best, in one place** (`candidates.py`). `Found` gains `best: tuple[Candidate, ...]`: the ten best
   (`KEPT = 10`, a constant) of the items found for the unknown **by the hand-set score** (`score.py`, as today),
   before the cut by `RECONCILE_LEAST_SCORE` and whatever `limit` was asked. `Found.candidates` is unchanged (it
   is, today, a prefix of `best` filtered by the least score: keep one function making both, so that they cannot
   differ). A candidate's features are what `Candidate` already holds: `scores` (each part's cosine, and
   `shared`'s score while its weight is above 0) and `len(shared)` (the count). Nothing more is asked of the
   database for it.
2. **What was offered: `PGReconcileShown`**, a plain node (no model, not in lists, search, RDF or vectors), one
   for each **stand-in and user**. A new module `decisions.py` holds the reading and writing; `api.py` only calls
   it. Written by the stored route (`GET /api/reconcile/candidates/{id}`, which now takes the current user) after
   the answer is made, **only when the answer's `status` is `"ok"`** and `RECONCILE_KEEP_DECISIONS` is true. It
   holds:
   - `stand_in` (id), `user` (the username, the key only), `key` (stand-in and user joined: the unique property,
     so that one constraint on one property does on both backends; if `structure.py`'s way offers a composite
     constraint that works on both, use that and say so), `at`;
   - `rows`: the `best` of that unknown, each `{id, type, scores, shared (the count, a whole number), score,
     displayed}`, `displayed` true for a row that is in the answer given (in `candidates` **and** left in by
     `api.answer`'s views: a candidate the reader may not see is not displayed). As one JSON text property, by
     score and then id, as ranked;
   - what makes the features comparable: `profile` (name), `signature` (the profile's, of the vectors **in use**,
     as `store.states()` has it), `parts` (JSON: each scored part's stored signature), `weights` (JSON:
     `settings.weights()`), `features` (a constant `FEATURES = 1` in `decisions.py`, raised when what a row holds
     changes; its comment says so).
   - **Ids and numbers only: no label of anything.**
   A second request for the same stand-in by the same user **replaces** the record (new `at`, new rows): one
   `MERGE` by the key in one write transaction. Two requests at once must leave one record and neither may fail
   the request (the constraint; a conflict retried or caught).
   A failure to write the record is logged (`logger.exception`) and the answer is still given: keeping a decision
   never fails a reader. While the database is read-only for a migration (see how other writes are refused then:
   `test_read_only_while_migrating.py`) nothing is written and nothing is logged as a failure.
   The payload route (`POST`) still writes nothing; its "nothing is written" tests are unchanged. The stored
   route's become "exactly one node more, and it is this one" (and none with the setting off).
3. **What was chosen: `PGReconcileExample`**, one for each stand-in. Made by a listener of `hooks.resolved`
   (`decisions.heard`, appended at the app's install if not already there, as `pangloss_review.notices` appends
   its function; it reads `RECONCILE_KEEP_DECISIONS` when called and does nothing when false), in **one write
   transaction** that:
   - reads the shown records of `resolution.stand_in_id` (of every user);
   - if `resolution.direct`, and there is one of `resolution.user`, and it is younger than
     `RECONCILE_SHOWN_FOR`: writes the example for the stand-in, **replacing** an earlier one of that stand-in
     (`MERGE` by `stand_in`, unique): the shown record's `rows`, `profile`, `signature`, `parts`, `weights`,
     `features` as they are; `taken`: the id of the row that is `resolution.entity_id`, among **all** the rows
     kept (displayed or not), or null when it is none of them (someone else, or an entity just made); `at` (when
     decided). **Who decided is not kept**, and no label;
   - in every case removes every shown record of that stand-in (it is gone from its document).
   The transaction may be run again by the driver: it does only what can be done twice.
   (11.5 works out "none of those offered" as: `taken` is null or names a row not displayed. Do not store that
   apart.)
4. **Structure**: `pangloss_reconcile/structure.py` and `migrations/0001_initial.py`, as `pangloss-vectors` has
   them: unique `PGReconcileShown(key)`, an index on `PGReconcileShown(stand_in)`, unique
   `PGReconcileExample(stand_in)`. Reading all examples is a scan of the label: no index wanted. The package's
   tests and the e2e project must still set up (see how `pangloss-vectors`' migrations reach the test database:
   the fixtures of `pangloss_testing`).
5. **Settings** (`settings.py`, each checked at `initialise()` with a message, as the others):
   `RECONCILE_KEEP_DECISIONS` (bool, true); `RECONCILE_SHOWN_FOR` (minutes, a number above 0, default 30).
6. **A sweep**: `decisions.sweep() -> int`: removes shown records older than `RECONCILE_SHOWN_FOR`, and those
   whose stand-in is no longer a node of a document (deleted with its document's rewrite; look how a nested node
   is found by its id, `stored.py`), in pages if there may be many. A new `cli.py`: `pangloss reconcile sweep`
   prints how many were removed. (11.5 adds `learn` to the same group and calls `sweep` first: leave room.) The
   CLI guide (`guide/cli.md`) and its test list every command: add it.
7. **Tests** (live, in `packages/pangloss-reconcile/tests/live/`, a new file `test_reconcile_decisions_live.py`;
   they must pass on Neo4j too). Each by name:
   - shown, then reconciled by the same user through `pangloss_review.reconcile.reconcile`: one example, the
     right `taken`, the rows as shown, the shown record gone;
   - reconciled with an entity that was not among the rows; and with an entity made just before: `taken` null;
   - reconciled with a row kept but not displayed (ask the route with `limit=1`): `taken` is its id, and that row
     `displayed` false;
   - never shown: no example;
   - shown to A, reconciled by B: no example, A's record removed;
   - shown, then older than `RECONCILE_SHOWN_FOR` (set the record's `at` back, or the setting small): no example,
     record removed;
   - an `also` mention with a shown record of its own (`direct` false): no example, record removed;
   - `in_form=True`: nothing happens (no event), the shown record stays until the sweep;
   - reconciled twice (the stand-in comes back with its id: by `pangloss-history`'s restore if the package's
     tests can have it, otherwise by calling `decisions.heard` twice with two `Resolution`s and saying so): one
     example, the later;
   - the answer `pending` and `rebuild_due`: no shown record;
   - two requests at once (`asyncio.gather`): one shown record, both answered;
   - a second request replaces the first's rows (`limit` changed: `displayed` differs);
   - a candidate the reader may not see is not `displayed`... only if a logged-in reader can be made not to see
     one in this package's fixtures; if not, say so;
   - an example and a shown record hold no label (assert on every property's text: the mention's and the
     candidates' labels are not in them);
   - a failure to write (monkeypatch the write to raise) still answers, and is logged;
   - the sweep (old; stand-in gone; a fresh one stays); the setting off (the route writes nothing, the listener
     nothing); each new setting's refusal by its message (pure, `test_reconcile_settings.py`);
   - the budget test of the stored route: say the old and the new numbers (one write transaction more, none with
     the setting off).
   Pure: `best` against `candidates` on a hand-made case (the cut by least score and `limit` does not touch
   `best`; `best` is at most ten, by score then id).
8. **Docs**: `implementation_docs/reconcile.md` (a section "Decisions kept": the two nodes property by property,
   when each is written and removed, what is no example and why, the settings, the sweep, the migration; 🚧 until
   11.5 uses them), `guide/vectors/reconcile.md` (the two settings; that the stored route now keeps what it
   offered, and how to turn it off; `pangloss migrate` is needed), `guide/cli.md`, the settings page if it lists
   the package's, the skill's row for `pangloss-reconcile`, `check_skill.py`.
