# 10.5f report (builder): choices as they were made

Written as the work goes; the summary is at the end.

## Found in the code before building

1. **A suggestion confirmed with several entities can raise no second event** (the brief asked to say so). After
   `identify.confirm` "as it is" with three, the node is an `IdentificationFromText` (no longer a suggestion):
   - review's confirm route (and "confirm as this one") finds only suggestions (`graph.suggestions_by_id`): no second
     confirmation of it is possible;
   - a save that collapses its target to one is noted by the library's `note_if_confirmed` only when it has URIs, and
     then with `was = None` (the node was an identification already); review's `_after_save` tells `hooks.confirmed`
     only when `was` is not None. So the collapse by a save raises nothing;
   - and the sweep (`suggesting.SWEEP_SUGGESTED_QUERY`, 10.5d) removes a `PGReconcileSuggested` whose node is not of a
     class of suggestion, so the rows kept would go at the next sweep anyway.
   So "the kept rows stay, and a later collapse to one is a decision" cannot hold with reconcile's code alone. **Not
   decided here** (a design question: either review raises `hooks.confirmed`, or another event, for an
   identification of several written again as one, which is review's and the library's code; or reconcile hears
   writes itself). Built: the listener writes nothing and removes nothing for several entities; the sweep is left as
   10.5d made it (the rows go at the next sweep); the test of the collapse is `xfail(strict=True)` with the reason.

## Choices

1. **The listener** is `decisions.confirmed`, installed by `decisions.install()` beside `heard`. It does nothing
   unless the app is installed and `RECONCILE_KEEP_DECISIONS` is true, and returns before any read when the
   confirmation's `entities` are not exactly one. One write transaction: read the `PGReconcileSuggested` by id (none:
   nothing, an outside toolchain's), `MERGE` the example, `DELETE` the record. `PanglossReadOnlyError` is swallowed
   as `heard` does; any other failure goes to `hooks.tell_confirmed`, which logs it.
2. **The example's properties**: `stand_in` (the key) = the suggestion's id; `rows` and the six `SIGNATURES` copied
   from the record (as kept at the time of the suggestion); `taken`; `at` = the confirmation's `at`; `via` =
   `"suggestion"` (`learning.VIA_SUGGESTION`); `direct`; `user`. The original stand-in's id is not copied onto the
   example (the tried row links them through its `suggested`). The brief asked for the user: so, unlike the dialog's
   examples ("who decided is not kept"), these keep it; said in `reconcile.md`.
3. **`taken` through a merge** (`decisions.taken_of`): when the entity is not among the rows' ids,
   `pangloss_cypher.validate_write.survivors_of(tx, rows + [entity])` (the existing helper: one statement when
   nothing is merged, one more for each step of a chain) and `taken` is **the row's own id** (the absorbed one), not
   the survivor's: `learning` compares `row["id"] == taken`, so the survivor's id would match no row. The entity is
   resolved to its survivor too (in case the event named an absorbed id).
4. **Several entities**: nothing written and nothing removed (main's call). The sweep is left as 10.5d made it, so the
   record goes at the next sweep (the node is no longer a suggestion). See "Found in the code", 1: the collapse-by-save
   test is `xfail(strict=True)`.
5. **The sweep's undone rule** (`decisions.UNDONE_QUERY`): one query, `OPTIONAL MATCH` of each example's node by id
   and a `CASE` on `via`: the dialog's as before (a node below a head); a suggestion's when its node is gone, has no
   `head_node_id`, or has a label of `hooks.unconfirmed_classes()` (or `RECONCILE_SUGGEST_AS` if none is registered,
   as `sweep_kept` does). A confirmed suggestion in a **deleted** document stays (as the dialog's rule takes a deleted
   document's stand-in as still there).
6. **The tried row on a confirmation** (the caller's rule, mend 6): the worker's `SWEEP_TRIED_QUERY` now also keeps a
   tried row while an example **keyed by its `suggested`** exists (a third `OPTIONAL MATCH`, by the same index). So:
   confirmed as one entity, the record goes in the listener's transaction, the example takes its place, and the tried
   row of the replaced stand-in **stays** while that example is there (a restore to the version before the suggestion
   still finds the stand-in tried). Without this, the tried row would have gone at the first sweep after the
   confirmation (the example is not keyed by the stand-in). When the example goes (restored to before the
   confirmation, or the node gone), the tried row goes at the same sweep (the example is removed first): the test
   asserts this. Confirmed with several entities, the record goes at the next sweep and the tried row with it, as
   before this step. This is a change to the worker's sweep rule; it widens what keeps a row, and changes nothing else.
7. **`RECONCILE_KEEP_DECISIONS = False` and the worker**: it did write `PGReconcileSuggested` regardless (checked:
   `suggesting.py` never read the setting). Mended: `Kept.suggested` is empty when the setting is false. The tried
   rows are still written (the worker's own bookkeeping). Consequence: a replaced stand-in's tried row (with
   `suggested`) then has no record and no example to keep it, so it goes at the first sweep, and a restore of the
   version before the suggestion is asked again. Said here, not mended (the worker's rule).
8. **`learn`**: `learning.decision_of(example)` (pure) reads `via`; `learning.from_suggestion`; `Decision.via` (a
   default of None, so every existing call is unchanged). `fits.learn` reads every example as before, leaves out those
   via a suggestion when the setting is False, and counts: `Learnt.suggestions_left_out`, `Learnt.suggested` (of the
   decisions learnt from), both in `counts()` (the admin job's). Printed: "N examples left out: of confirmed
   suggestions (RECONCILE_LEARN_FROM_SUGGESTIONS is False)" when any, and "N decisions to learn from, M of them of
   confirmed suggestions" when M > 0 (the line is unchanged otherwise). The fit's record gains `suggested`; `fits.write`
   takes it as optional (`OPTIONAL`), so 11.6's tests that plant fits through it are unchanged; older fits read null.
   The "nothing new since the fit" check is unchanged (the count of decisions differs when the setting flips with any
   suggestion example kept).
9. **The setting** `RECONCILE_LEARN_FROM_SUGGESTIONS` (True), `settings.learn_from_suggestions`, `_true_or_false`,
   checked at `initialise()`, in the docstring and `__all__`; added to the live conftest's settings (a test sets it).
10. **Tests**: one new live file, `tests/live/test_reconcile_learning_from_people_live.py` (13 tests, one `xfail`). It
    reuses the worker's live file's models, world and helpers by import, and its fixtures by assignment (as
    `pangloss-api`'s tests import from `test_model_routes`). Where the brief says "confirmed as it is with three", the
    test world has two Jon Smyths: the test uses `RECONCILE_SUGGEST_WITHIN = 0` and asserts more than one alternative.
    "Someone else" is a person made after the worker asked, so that it is surely in no row (the small world has six
    people and ten rows are kept: any of them may be a row). Added beyond the list: an entity merged since (finding 9). Pure: `test_reconcile_learning.py` +1,
    `test_reconcile_settings.py` +6 (the default, four refusals, one more of the `initialise()` parametrisation).
11. **Seen failing**: with `UNDONE_QUERY` as before, the merge resolution taken out, the worker's keep-decisions mend
    taken out, and the tried rule's third match taken out (all at once, src files copied back after), 4 of the new
    live tests failed, each at its claim (merged: `taken` None; swept/restored: no example after the sweep; `learn`:
    the example swept by `learn`'s own sweep, no fit; keep off: a record kept).
12. **One existing test changed**: `test_reconcile_learn_live.py::test_the_admin_job_learns_with_its_counts_and_its_report`
    expects the two new keys of the admin job's counts (`suggestions_left_out`, `suggested`, both 0).
