## What to build

### 1. `StandIn.named_type`

A new optional attribute of `hooks.StandIn`: `named_type: str | None = None`, "the name of a property of the
document that holds the name of the one entity class this value stands for (review's `unreconciled_type`); None
if the document does not say (it stands for whatever its field takes)". Review's `STAND_IN` gives
`named_type="unreconciled_type"`. Nothing reads it yet. A pure test in `packages/pangloss-models/tests` beside
the stand-ins' existing tests (default None; a frozen dataclass still), and one in review's unit tests that its
stand-in names the property and that the property is a field of `Unreconciled`.

### 2. `checked_create`

In `pangloss_cypher.write_functions` (exported as the write functions are; if the generated models bind the write
functions through the backend, **do not** add a model method: this is a function a package calls):

    async def checked_create(instance, *, created_by=None, toolchain=None, published=None, review_status=None)
        -> tuple[db_instance, WritePlan, existing]

"What a create does before it writes, and nothing after: the database model, its plan, and the entities written
in it that exist. Raises what the create would raise. Nothing is written, nothing is announced, nothing marked."
Take the same optional arguments the create takes only as far as they change what is checked or what the plan
holds (the head's `published` and review status come from `hooks.properties_for_new_head` under
`requesting_review_status`: the plan this gives must have the head properties the write's plan would have). It
runs, in the order the write runs them: `citations.resolve`, `to_db_model` under `writing_as`, `fill_labels`,
`check_before_create`, then **in a read transaction**: `plan_create` (+ `computed.give_bases` where the write
does), `checked_plan`, `citations.check_before`, and the checks `write_head_nodes`/`write_head_node` make first
(`check_user_exists`, `check_creators_exist`) if the single create makes them.

**Refactor so the two cannot drift**: the create and `checked_create` should share one function for the part
before the write and one for the checks inside the transaction, not two copies. Keep the create's behaviour and
its query count exactly as they are (`test_query_costs.py` has budgets: run it). If a check of the write cannot
run in a read transaction on either backend, stop and say so in the report.

Things to find out and say in the report: whether `citations.resolve` or `fill_labels` change the instance given
(the caller's `Create`) and whether that matters for a caller that uses it afterwards; whether anything on this
path writes (a hook, a lock, `MERGE`); what `before_create` hooks do that could write (they are the project's:
say it in the docstring if they are run).

### Tests

- Conformance, `packages/pangloss-testing/src/pangloss_testing/conformance/test_checked_create.py` (runs on both
  backends through each backend's conformance run): with models of the kind the neighbouring tests declare,
  - the counts of nodes, of edges, and of `PGPending` nodes are the same before and after a `checked_create` that
    passes, and no write event is announced (a listener on `hooks.after_write`);
  - the plan it gives equals `plan_create` of the instance a create of the same payload writes, as far as can be
    compared (head type, properties but ids/timestamps, the walk's relations); then the same payload created
    still succeeds (nothing was reserved);
  - each refusal is the write's, compared by exception class and message with the create of the same payload: a
    reference to an entity that is not there; an id that is taken; a URL that is taken; a `@before_create` that
    refuses; a citation of something that is not there or cannot be cited (follow `test_citations.py` for what a
    create refuses); and after each refusal the counts are unchanged;
  - a class with a label template has its label filled in the plan's head.
