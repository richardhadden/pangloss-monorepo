The query of `reasons.py` asked for **every** candidate found (95 at the median) takes 10 ms at the median on
Memgraph (slowest 20 ms) and 8 ms on Neo4j (slowest 166 ms). So: no new query text is needed; it is asked once,
earlier, for all of them.

## What to build

1. **The count, before the cut.** `candidates_of` asks `reasons` once for a request: every candidate found, of
   every unknown asked about (the union), uncut (every shared entity with its count of documents). Each
   `Candidate` gains what it shares (the pairs `(entity id, documents)`, most documents first then id, all of
   them) so that `api.answer` shows the first `RECONCILE_REASONS` of them **without asking again**: one reasons
   query a request, where there were one. `RECONCILE_REASONS = 0` shows none and no longer decides whether the
   count is made. The query is not asked at all only when the weight of `shared` is 0 **and** `RECONCILE_REASONS`
   is 0, or nothing was found. The reader's cut is the query's own, unchanged.
2. **The score.** `score.py` (still no database in it): `shared_score(n) = n / (n + 2)`; for every candidate,
   `scores["shared"]` is that, **whenever the weight of `shared` is above 0** (0 for a candidate that shares
   nothing, and for a document that names no entity: always in the sum below the line, so that a score means the
   same from one document to the next). The score stays the weighted mean, 0 to 1. The module's docstring says
   what `shared` is and why it is not a part (it has no vector; it is a count asked of the database).
3. **Settings.** `RECONCILE_WEIGHTS` may name `"shared"` beside the parts (the refusal "which is not a part" lists
   `shared` among what may be named); `weights()` gives `shared` at **0.75** unless it is given (`{"shared": 0}` is
   phase 10's score exactly: a test says so). The check "no part above 0" stays about the parts the profile weighs
   (`shared` alone is not enough: with no part nothing is found). A new `RECONCILE_LEAST_SCORE` (a number from 0 to
   1, default **0.2**, checked at `initialise()` with a message): both routes leave out candidates scoring under
   it, after ranking and before the cut to `limit` is fine either way but say which. A query parameter is not
   wanted.
4. **The interface module.** `LEAST_SCORE` and its filter go from `candidates.ts` (the server cuts now), with
   their tests changed, not deleted; the bar's title (`partsText`) lists `shared` with the parts, under a
   translated name ("named with" / German / French, a `t()` slot as the others); nothing else of the look changes.
   Run the module's vitest and type check, and `e2e/test_reconcile_candidates.py` (its own ports).
5. **Tests.**
   - Pure (`test_reconcile_score.py`, `test_reconcile_settings.py`): `shared_score`; the mean with `shared`;
     weight 0 gives phase 10's scores and no `shared` key; the settings and each refusal by message.
   - The seeded floor, `tests/test_reconcile_planted.py`: the world's shared count worked out in memory as
     `notes/similarity-evaluation/learn_trial.py` does (`world_features`: the entities the mention's factoid names
     beside the mention; a candidate named with one of them in another factoid; **a candidate does not share
