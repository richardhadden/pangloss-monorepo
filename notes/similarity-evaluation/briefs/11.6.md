## What main decided

- **The ranking stays hand-set.** The trial (the plan, "What was found before the steps", point 3) found a fitted
  ranking no better at size and much worse on few decisions. So no `likelihood` on a candidate, no order by a
  model: the ranking model 11.5 fits is recorded and used by nothing. Do not build the other branch.
- **The stored route's answer** (`GET /api/reconcile/candidates/{id}`) gains:
  - at the top, `model`: `null` when no fit is in use; otherwise `{"id", "at", "decisions", "used"}` of the fit in
    use, `used` false when it is **not today's** (its profile, signature, parts' signatures, weights or
    `features` differ from what this request's rows are made with: the one function that says "today's", from
    11.4/11.5) or when it has no "none of these" model;
  - on each unknown, when `model.used` and its list of candidates **as answered** is not empty and every feature
    the model weighs can be made (`learning.head_features` of the rows answered, the same function 11.5 fitted
    on; a row lacking a part the model weighs: no figure): `new`, the likelihood from 0 to 1 that the one meant
    is none of those offered (`Model.score`), and `probablyNew`, whether it is above `RECONCILE_NEW_ABOVE`.
    Otherwise both keys are **absent** (not null, not 0).
  The rows the features are made of are exactly those the answer gives (after the least score, `limit` and the
  reader's views), in the answer's order: what the person sees is what the figure is about.
- **The payload route's answer is unchanged** (no `model`, no `new`: its features differ a little from the
  stored route's, fault 17). A test says so.
- **`RECONCILE_NEW_ABOVE`**: a number from 0 to 1, default 0.5, checked at `initialise()` with a message.
- **The cost**: reading the fit in use is one small read (by `in_use`; an index if `structure.py` wants one, in
  the migration 11.5 made if that is still uncommitted in the tree, else a new one). Put it in a transaction the
  route already runs if one fits; otherwise one read transaction more. The budget test says the old and new
  numbers. Nothing is written by it; what 11.4 keeps (`PGReconcileShown`) is unchanged and does **not** hold
  `new`.
- **The interface module**: `UnknownCandidates` gains `new?: number` and `probablyNew?: boolean`,
  `CandidatesAnswer` `model`. In `ReconcileCandidates`, when the mention's unknown is `probablyNew` and there are
  rows: one quiet line between the heading "Suggested" and the rows, `t("reconcile_probably_new", "Probably not
  in the database yet")` (German and French in `translations/ui.jsonc`), its `title` the figure as a percentage
  (`t("reconcile_new_likelihood", "{percent} likely to be none of these")`), `data-testid="reconcile-probably-new"`.
  Nothing is hidden and nothing reordered: the suggestions stay. Slate only, text-xs, as the "also named with"
  line; no new component kinds, no CSS. The working-out (is the line shown; the percentage text) is a function in
  `candidates.ts` with unit tests, as the others.
