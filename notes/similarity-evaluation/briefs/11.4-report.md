# Step 11.4: the builder's report (kept as it went)

## Choices made where the brief left room

1. **The unique key of a shown record**: a composite unique constraint on `PGReconcileShown(stand_in, user)`, no
   `key` property. `structure.py`'s way offers it (`pangloss-calendar` ships composite unique constraints, made by
   both backends' migration code: `CREATE CONSTRAINT ON (n:L) ASSERT n.a, n.b IS UNIQUE` on Memgraph, `REQUIRE
   (n.a, n.b) IS UNIQUE` on Neo4j). The `MERGE` is by both properties.
2. **An index on `PGReconcileExample(stand_in)` beside its unique constraint** (the brief named only the unique
   one): Memgraph's unique constraints make no index, so the listener's `MERGE` by `stand_in` would scan every example
   without it (as `pangloss-derived` pairs each unique key with an index). On Neo4j the constraint's own index serves
   and the migration code does not ask for the plain one (`pangloss_neo4j...schema`: "an index that a constraint
   gives is not asked for").
3. **`Found.best` and `Found.candidates` from one function**: `candidates.ranked(...)` (it replaces `_scored`) scores
   every item once, orders them by score then id (`score.ranked`), and gives `order[:KEPT]` and the first `limit` of
   those not under the least score. Those above the least score are a head of the one order, so the candidates are
   always a head of `best` where they meet. `KEPT = 10` in `candidates.py`.
4. **`api.answered(found, see_unpublished) -> (answer, states)`** beside `api.answer` (which calls it), so that the
   stored route gives `decisions.keep_shown` the `store.states()` the answer read: no read more.
5. **The stored route takes `user: CurrentUser`**, and `dependencies=LOGGED_IN` (now unused) is gone; FastAPI asks the
   login once either way (the budget shows no transaction more with the setting off). The user kept is
   `user.username`, which is what `get_current_user` sets `current_request_username` to (the user of a `Resolution`).
6. **`displayed`** is worked out from the answer itself (`decisions.displayed_in`: the ids of the unknown's candidates
   in the answer, after the views): a candidate the answer left out is not displayed.
7. **`parts`**: the parts in the rows' `scores` (but `shared`), each with `store.states().parts[part].signature`; an
   empty list keeps `{}`. A record is still written for an `ok` answer with no rows (the brief says "only when ok", and
   11.5 leaves out empty lists).
8. **`at`** is a UTC datetime (as `pangloss-vectors` keeps `built_at`), compared in Cypher by the sweep
   (`s.at < $before`) and in Python by the listener (the resolution's `at` against the shown record's).
9. **A conflict at the same moment**: on Memgraph two `MERGE`s of the same key either conflict (a `TransientError` the
   driver retries itself) or both create and the second commit is refused for the unique constraint (a `ClientError`,
   "Unable to commit due to unique constraint violation"; seen in the test). `keep_shown` tries such a write up to 3
   times (`WRITE_TRIES`), recognising Neo4j's `ConstraintError` and any driver error whose message names a constraint;
   anything else, or a third failure, is logged. The route-level test (4 requests through `asyncio.gather`) and a
   below-the-route one (8 `keep_shown`s at once, where the constraint path was seen taken) both leave one record.
10. **Read-only**: `PanglossReadOnlyError` (raised in the write transaction while the migration lock is held) is caught
    and nothing is logged, in `keep_shown` and in `heard`.
11. **`heard` does nothing unless the app is in `INSTALLED_APPS`** (as `settings.check` does), besides the setting: the
    listener is appended at import, and a process that imports the package without installing it (another
    package's tests, say) should not run a transaction for every resolution.
12. **The sweep**: one query in pages (`SWEEP_PAGE = 1000`): `OPTIONAL MATCH (n:PGIndexableNode {id: s.stand_in})`
    and removed when older, or `n` is missing or has no `head_node_id`. A stand-in in a soft-deleted document is not
    "gone" by this (it is still a node below a head); the age removes it within 30 minutes anyway.
13. **The CLI**: `pangloss_reconcile/cli.py`, a group `reconcile` with a callback (as `pangloss_names`), so 11.5 can
    add `learn`; it uses `pangloss_vectors.cli.run_connected`. Prints "N records of what was offered removed".
14. **The test database has no app structure**: `initialise_database` (the fixtures') makes the core's indexes and
    constraints, not `installed_app_structure`'s. So `test_reconcile_decisions_live.py` applies the package's
    `0001_initial` itself in an autouse fixture (as `pangloss-calendar`'s live tests do: a second time it changes
    nothing). Without it the "two at once" test found 5 records: there was no constraint.
15. **"Reconciled twice"**: `pangloss-history` is no dependency of the package's tests, so the test tells
    `decisions.heard` twice, of two `Resolution`s, each after a list shown (limit 10, then 1): one example, the later
    (taken the namesake, displayed only Jon). Said in the test's docstring.
16. **"A candidate the reader may not see"**: cannot be had through the route (every candidate is an entity, never
    unpublished, and a logged-in reader sees what is not published). Tested below the route: `keep_shown` given an
    answer that leaves Jon out records him `displayed: false`.
17. **The test of "nothing is written"** in `test_reconcile_candidates_live.py` is renamed
    (`..._nor_by_the_payload_route_and_the_stored_route_writes_only_what_it_offered`): the payload route and
    `candidates_of` unchanged; the stored route, with the setting off, writes nothing; on, exactly one node more,
    a `PGReconcileShown` of that stand-in for `root`, no edge, no write event.
18. **`test_each_number_is_checked_at_initialise`** became `test_each_setting_is_checked_at_initialise` (it now has the
    two new settings, one of them a bool).
19. **The live tests' world for decisions** is review's own models (`reviewed_models` of the candidates' tests, review's
    `Unreconciled`), so that review's `reconcile` raises the event; the factoid with the mention is saved unpublished
    and the mentions' ids read from the database (`save(detail=True)` gives None for a reader who may not see it).
    The fixtures `database` and `client` and the helpers are taken from `test_reconcile_candidates_live.py`.
