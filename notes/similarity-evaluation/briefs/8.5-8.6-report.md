### 8.6 By a name: done (the measuring part of 8.6 is main's and was not done)

- `pangloss_names/by_name.py`:
  - `vector_of(text | names)` weighs by `PART.rarity()` (the kept table) and the table of variants. It gives None
    when the text has no letter or digit.
  - It raises `NotBuilt` if the part has never been built. `NotBuilt` is a subclass of `store.RebuildDue` and tells you
    to run `pangloss vectors rebuild`. If the part is built but its table is gone, `PART.rarity()` raises
    `RebuildDue`.
  - `search(text, *, types, profile, k, see_unpublished)` calls `nearest(vector={"name": v}, ...)`.
  - The profile is the one you name, or the first one by name that weighs `name`. Otherwise it is a `ValueError` that
    gives `VECTORS_PROFILES = {"who": {"name": 1, "graph": 0.25}}` as the example. Naming a profile that does not
    weigh `name`, or one that does not exist, is also a `ValueError`.
  - `types` are expanded to their concrete classes (`fields.classes_of`) and passed with `asked=`, as the route does.
- `pangloss names search TEXT [--type NAME ...] [--profile NAME] [-k 10]` (`pangloss_names/cli.py`):
  - It prints one line per hit: score, class, label (from `views.reference_views`) and id.
  - It shows unpublished documents (`see_unpublished=True`).
  - Exit codes: 2 for a `ValueError` (a profile, a class, an empty text), 1 for `RebuildDue`, `pending` or
    `rebuild_due`.
- `guide/cli.md` has a section for it, and `test_cli_guide.py` has `pangloss_names` added to `APPS`.

**What a hit's score means.** `Layout.combine` puts each part's unit vector, times the square root of its weight, end
to end. A query from a name has zeros in the other parts, so:

`score = cos(names) × sqrt(w_name / Σ w of the parts the hit has a vector of)`

- With `who` (name 1, graph 0.25): 0.894 × the name cosine for a hit that has a graph vector, and the name cosine
  itself for one that has none.
- Among hits with the same parts, the order is the order of the names.
- A hit with fewer parts is lifted above one with more. The score is not the name cosine, and scores from different
  profiles cannot be compared.

This is written in `by_name.py`'s docstring, `names.md` and the guide row.

## 4. Choices the brief did not decide

- **`settings.variants()` keeps its shape**: the canonical forms with their variants, as written in the file. The part
  folds them with `maths.variants_table` in `PART.table()`, unchanged. I did not change both.
- **`variants_hash()`** is `signature_of(variants_table(variants()))`. With no table it is `signature_of({})`, which is
  what the part's signature already held, so no stored signature changes for a project without a table.
- **A relative path is resolved against the directory of the settings module** (the file of
  `type(settings).__module__`). If that module has no file, the working directory is used. I found no other setting
  that names a file, and `initialise()` does not know the project's root.
- **Refusals the brief did not list**:
  - A canonical form on two lines (a dict would silently keep one).
  - An empty cell (`Johannes,Hans,`), refused as "a cell is one word".
  - A file that is not UTF-8.
- **A variant that folds to its own form is skipped**, as `maths` does.
- **Encoding**: read as `utf-8-sig`, so a spreadsheet's byte-order mark is not part of the first form.
- **The variant table is remembered** by settings-object identity plus the value of `NAMES_VARIANTS`, so a test or
  monkeypatch that changes the value reads the file again.
- **`NotBuilt` subclasses `RebuildDue`**, so the CLI and callers handle one kind of error.
- **`search` raises `ValueError` for a text with no letter or digit** rather than returning nothing.
- **A one-command Typer needs `@cli.callback()`**, or Typer collapses the group into the command and
  `pangloss names search` does not parse.
- **The vector index in the live tests**: `test_names_search_live.py` has a small `make_vector_indexes` of its own,
  copied from `pangloss-vectors`' test support, which other packages cannot import. Searches that are not narrowed to
  a class ask the profile's index, which a migration makes. It could move to `pangloss_testing.parts` if it is wanted
  in a third place.
- **The async live tests are marked one by one** (`on_the_loop`), since the command test is synchronous.
