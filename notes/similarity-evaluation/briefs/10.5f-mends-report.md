# 10.5f mends report (builder): choices as they were made

Written as the work goes; the summary is at the end.

## Found in the code before building

1. **Point 3 can happen** (traced): `pangloss_history.restore.restore` validates the recorded version as the
   model's `Update` and saves it (`update.save(expected_version=..., restored_from=version)`). The library's
   `Identification.note_if_confirmed` is a `@before_update`: restoring a version where the node was an
   identification over a version where it is a suggestion notes it (`was` the suggestion's class, `by` the restorer);
   review's `on_write` takes it and `_after_save` tells `hooks.confirmed` as the restorer. What tells a restore:
   `WriteEvent.restored_from` (an int, set by `write_functions` from `save(restored_from=)`; history's listener reads
   it the same way). Nothing new is needed.
2. **The kind of a person** in `pangloss_users`: `User.kind: Literal["user", "toolchain"]`, default `"user"`; a
   `PGUser` node made by hand (the tests' `MERGE (:PGUser {username})`) has no `kind` and no `disabled`, and reads as
   a person not disabled. **The default user of scripts**: `pangloss_users.current_request_username`'s default,
   `"pangloss_default_user"` (a user made by hand, `implementation_docs/users.md`; it must exist for a script's
   write to be made).
3. **Point 6, the worker's own write**: the worker only replaces stand-ins by suggestions (`suggesting.py`); it never
   writes a suggestion again as an identification, and review's `_after_save` returns for a write by a toolchain
   anyway. So it cannot raise the hook: said in the test's docstring, the test kept.

## Choices

1. **Point 1, what an earlier example is**: an example of the suggestion's id with `via: "suggestion"`. The listener
   reads the worker's record first; when there is none, that example (its rows and six signatures are the worker's,
   copied from the record). One entity: the example is written again (the same `MERGE`) from those rows, `taken`
   worked out against them, this confirmation's `user`, `at`, `direct`. Several entities: the earlier example is
   removed; a record, if there is one, is left (as 10.5f). Neither record nor example: nothing. All in the
   listener's one transaction. **Depends on the sweep's timing** (not mended): if a sweep runs between the restore
   and the second confirmation, it removes the example (its node is a suggestion again), and the second
   confirmation then finds neither and makes nothing, as before.
2. **Point 2, who is a person**: `PGUser` with `coalesce(kind, 'user') = 'user'` (`pangloss_users.User.kind`) and
   not `coalesce(disabled, false)`; read in the transaction, first (`decisions.CONFIRMER_QUERY`, one statement by
   `username`). The default user of scripts is checked before any read, by name: the default of
   `pangloss_users.current_request_username`, read in an empty `contextvars.Context` (so the literal
   `pangloss_default_user` is not copied). Otherwise nothing at all is written (not even an earlier example
   removed), logged at info on `pangloss.reconcile` ("The confirmation of ID by 'USER' is not learnt from: why").
3. **Point 3** is mended in review's `_after_save` (where `on_write`'s background work tells it), by
   `event.restored_from is not None`: no `hooks.confirmed`; the URIs given as before. Tested in conformance (a save
   with `restored_from=1`, which is what history's restore does) and in reconcile with history's real restore
   (Ann's version put back over the suggestion by Bob: Ann's example unchanged).
4. **Point 4**: `decisions.taken_of` now gives **the list** of the rows that are the entity (`list[str]`, was
   `str | None`), and **always** reads the survivors of the rows and the entity (`survivors_of`, one statement when
   nothing is merged; it used to read only when the entity was not among the rows as they stand, but then a row
   merged into an entity that is itself a row could not be seen). More than one: no example, logged at info; the
   worker's record and any earlier example are removed (the record is consumed by the confirmation as when an
   example is made; kept, it would only go at the next sweep).
5. **Point 5 is cheap and done**: `ConfirmedInWrite.entities` (the library), worked out in `note_if_confirmed` from
   the target the write gives (`entities_named`, over the write's models or dicts: each entity's id and class in
   their order); `_after_save` uses them, and reads `graph.candidates` only when they are not said (None) or for the
   URIs. The entities are as written: an entity named by an absorbed id is that id (the listener resolves merges).
   `models.pyi` regenerated (`framework_stubs`).
6. **Point 6, `RECONCILE_KEEP_DECISIONS` on at the record, off at the confirmation**: none (the brief's lean), the
   setting read at the confirmation; the record stays, for the sweep.
7. **Point 6, the worker's own write**: it cannot turn a suggestion into an identification: said in the test's
   docstring, the test kept as it was.
8. **Docs**: `reconcile.md` ("A confirmed suggestion": who is a person, confirmed again, two rows merged, a save's
   entities; the sweep's note; a "Known limits" list of the brief's four, and the sweep-timing one of choice 1),
   `review.md` (where `hooks.confirmed` is described: the entities noted in the write; a restore is no judgement),
   the comment over `hooks.Confirmation` (a restore is told nothing), the skill's reconcile row (a person's
   confirmation, never for a restore, replaces an earlier one). Not `similarity-build-plan.md`, not `TODO.md`.
