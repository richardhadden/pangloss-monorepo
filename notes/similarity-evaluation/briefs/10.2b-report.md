## Choices, as made

1. **The suite's stand-in is declared by `similar_models.declare(stand_in=True)`** (a document `Mention` with a
   label and `mentioned_type: str`, `create_directly=False`), and the `hooks.StandIn` that makes it one
   (`document="Mention"`, standing for `Person` only, `named_type="mentioned_type"`) is registered by the suite's
   test before `declare` and removed after it, in a `try/finally`. Not always declared: a class more would be a
   dimension more of the class part in every other test of the suite. `pangloss-testing` gains no dependency.
2. **The place of the stand-in in the suite's payload**: beside Ada in the `InRole` of the overlay claim's factoid
   (`participants[0].target`: Ada and "Ivo Unknown"), so the unknown is joined to the activity, Gus, Fay and the
   place through the activity. `overlay_payload` gains a keyword `beside` (more targets of that `InRole`), used by
   the new claim only.
3. **How the claim is made exact**: the instance planned is the instance written (as the overlay claim does);
   the person is made with the unknown's id (`Person` of `similar_models` is `create_with_id=True`:
   `Person.Create(id=..., create_new=True, label="Ivo Unknown").save()`); then in that very `CreateDB` the `Mention` in the list is
   replaced by a reference to that person of the class of the reference beside it (Ada's), and the instance is
   written with `write_head_node`. Every nested id is the plan's, the person's is the unknown's.
4. **Which unknowns a part is asked of, in `unknown_vectors`**: only those whose class has vectors
   (`meta.included(type)`): the store leaves out the rows of a class without vectors, so a part's word for one
   would be of a vector no entity of it has. A part asked directly is not filtered.
5. **The class part, for a class with classes below it, gives the class's own vector; for an abstract class, its
   own vector too** (the class part has a dimension and a vector for every declared class, abstract ones as well:
   its class at 1 and those above it, as near each class below it at one depth). No entity can be of an abstract
   class, so for one the claim "the vector of an entity made in its place" has no entity to be; this is the vector
   that says only what is known. A name that is no class of documents or entities: nothing. The labels given are
   those of the class (`labels_for_model`, without `__labels_unmanaged__`): a new entity fulfils nothing.
6. **The name part's rule**: `label` is a name of an unknown's class when it is among the name fields of that class
   (`meta.named()`) if the class is concrete; for an abstract class, when it is among those of any concrete class
   below it (`label_is_a_name`). The vector is of `[label]` alone, by the kept table and the table of variants: a
   stored entity of the class with that label and its other name fields empty has the same. Nothing with no table
   yet, or a label that gives no vector.
7. **The graph part**: `_overlaid(plan, entities=None)` is the one reading (`_resolved`, `laid_out`, `in_thread`,
   `maths.overlay`) of both `overlay_plan` and `unknown_plan`; `laid_out` gains `entities` (id → class). Below a
   node laid out as an entity nothing is laid out (its relations, the documents below it, and an entity written
   in it for the first time there: a walk visits an entity written in a document at its first place only, so an
   entity first written below a stand-in and named again elsewhere is not laid out at the second place either; an
   edge case of a stand-in that holds an entity, which review's `Unreconciled` cannot). `stop_class`: the class
   itself if the maps have it as a stop; none if they have it as anything else (`FastRPMeta(include=False)`: such
   an entity has no graph vector); if they have it not at all (abstract), the first concrete entity class below it
   that is a stop, in the order of names.
8. **`VECTORS_GRAPH_SEES = "everyone"`**: the stored vectors of the entities around an unknown are not read (the
   maths reads the graph, not stored vectors), but the graph read follows the setting, so other unpublished
   documents are out of it, and only the plan's own nodes are taken as published. That is what the brief intends:
   the unknown's vector is the one the entity would have once this document is published, and nothing of any
   other unpublished document reaches it.
9. **A label of spaces only** is no label (`label.strip()`), as an empty one.
10. **Fault injected to check the claim bites**: the graph part's unknown vectors scaled by 1.001: the suite's claim
    fails ("differs by 3.93e-04"); put back.
