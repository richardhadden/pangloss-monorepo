# Report: step 7a.2, a URI at the similar route (written as the work goes)

## Checked first

- Point 1 of the brief, by a request (a bare FastAPI app with the same routes and order, /tmp/probe72/probe.py):
  `/api/Person/http://x.org/a/similar` is taken by `/{model_name}/{ref:path}/similar` with
  `ref = "http://x.org/a"`; `…/similar/similar` gives `ref = "http://x.org/a/similar"`; `http:/x.org/a/similar?id=7`
  gives `ref = "http:/x.org/a"` (the query is not in the path). Confirmed; the live tests confirm it on the real app.
- **Found, not in the brief**: the new path also matches routes of other apps that end in `/similar` and have more
  than one segment after the app's prefix: `/api/review/unreconciled/{id}/similar` and
  `/api/review/identifications/{id}/similar` are matched with `model_name = "review"`,
  `ref = "unreconciled/{id}"` whenever `pangloss_vectors` is listed in `INSTALLED_APPS` before `pangloss_review`
  (shown by the same probe). The demo lists review first, so it is not broken there, but a project need not.

## Choices

- Against that: the similar route is of a route class of its own (`ModelRoute` in `pangloss_vectors/api.py`) whose
  match is no match when `model_name` is not the name of a routable model, so that the request goes on to the routes
  after it. Local to `pangloss-vectors`; nothing in the core. A consequence: `/api/Nothing/{id}/similar` is now the
  router's plain 404 ("Not Found"), not "There is no model 'Nothing'" (still a 404; the test of it asks only the
  status).
- `pangloss-api`: `reference_from(request, ref, own)` in `routes/models.py` (the query string less the route's own
  parameters, then `parse_reference`); `entity_reference` calls it with `OWN_PARAMETERS`. A pure test beside the URL
  test in `tests/test_model_routes.py` (there were no separate pure tests of `parse_reference`).
- The similar route's own parameters: `SIMILAR_PARAMETERS = {"profile", "type", "limit"}` (`field` left for 7a.4).
- Order of checks in the route: the model (404), the reference (422 if neither), a URL at a document class (422),
  then profile and type as before.
- `resolve_id` of a merged entity's URL: a merge moves the URLs to the survivor (`merge.py`, "Its URLs become the
  survivor's"), so the URL already names the survivor; `survivors_of` after it changes nothing then, and stays for an
  id.
- The 404 at a URL: `not_found(model, reference)`'s text plus " (an entity whose URL itself ends in /similar is read
  by its id: at its URL, this route takes the URL without the /similar)".
- The test of the `/similar` consequence reads `GET /api/Person/{id}` on an app made after the test's models (the
  `client` fixture's app is made before them and has no model routes for them).
