# Report: step 10.2a (the core: `StandIn.named_type`, `checked_create`)

Written as the work went (2026-11-22), by the builder.

## Choices, as made

1. **`checked_create` takes `review_assigned_to` as well** as the four the brief lists. The brief's rule ("the same
   optional arguments the create takes only as far as they change what is checked or what the plan holds") takes it
   in: review's `requested_assignment` puts `review_assigned_to/by/at` on the plan's head, and refuses
   (`PanglossAssignmentError`) when someone who is not an admin gives the document to another. `detail` changes
   neither, and is left out.
2. **It refuses a document that cannot be made on its own** (`refuse_unless_created_directly`), first, as
   `Document.Create.save` does (the models bind that refusal in front of `create_head_node`, so `create_head_node`
   alone does not make it). Without it, `checked_create` would pass what the create refuses.
3. **It refuses while a migration runs** (`refuse_while_migrating`, first in its read transaction, skipped while
   this process bulk-loads), since a write does (`Database.run_write` runs it before the write's function). One more
   read query, on `checked_create`'s path only: the create's path and count are unchanged.
4. **It is reached as the write functions are**: `pangloss_cypher.write_functions.checked_create`, re-exported by
   `pangloss_cypher.operations` (`storage_of().operations.checked_create` on both backends). No model method.
5. **What the two share**, in `write_functions.py`: `_prepare_create(instance, creators)` (resolve, `to_db_model`
   under `writing_as`, `fill_labels`, `check_before_create`): the part before the transaction;
   `_asking(published, review_status, creators, review_assigned_to)`: the context the transaction runs under;
   `_check_writer(tx)` (user, creators) and `_check_new_head(tx, db_instance)` (`plan_create`, `give_bases`,
   `checked_plan`, `citations.check_before`): the checks inside it. `create_head_node`, `write_head_node` and
   `_write_new_head` use them; `write_head_nodes` uses `_check_writer` (it had the same two lines).
   `create_heads` is left as it was (its preparation of several heads, with labels known from the earlier ones,
   is its own).
6. **The conformance test reaches `plan_create` of what the create wrote** through the `after_write` event's
   payload (the `CreateDB` written), and compares plans by a `shape` (head type, labels, properties without ids and
   times, URLs; each step of `walk`: edges, edge properties, first or not, the target's kind and its stable parts).
   Head properties that the apps add are compared with the stored node instead (a test hook on
   `new_head_properties` that writes the review status asked for), since `plan_create` outside the write's context
   would not have them.
7. **Pending marks**: the test fixture registers a kind of pending work for every class, so that a write would
   leave a `PGPending` mark (the test checks the create does), and `checked_create` leaves none.
8. **Two refusals beyond the brief's list are tested**, as they go through the shared `_check_writer`: a creator
   that is not a user (`created_by="no_one"`), and a request user that does not exist. And the refusal of a
   document that cannot be made on its own (choice 2).

## Things found out

- **`citations.resolve` changes the caller's `Create`** in place: a citation of something an installed app resolves
  (`hooks.resolve_citation`: only `pangloss-derived`, a citation of a derived document) is replaced by a
  `PGCitedBasis` with citations of what it rests on. The create does the same to the same object. It matters to a
  caller that uses the `Create` afterwards only in that the payload now cites the bases: saving it after works (the
  bases are checked again on the write, `check_bases`), and comparing it with what was sent would differ. Without
  such an app it changes nothing (the test checks `model_dump()` before and after).
- **`fill_labels` changes only the `CreateDB`** (its labels, `label_auto`), not the `Create`. Nor does `to_db_model`
  change the `Create`; each making of the `CreateDB` gives new ids to the nodes the payload gave none, so the ids of a
  plan from `checked_create` are not those a later create writes.
- **Nothing on the path writes** in the core: the checks of `checked_plan` (`find_existing_entities`,
  `check_references_exist`, `check_ids_available`, `check_urls_available`), `check_user_exists`,
  `check_creators_exist`, `citations.check_before` (`TARGETS_QUERY`) and `refuse_while_migrating` are `MATCH` and
  `RETURN`; `read_labels` is a read transaction; `plan_create`, `give_bases` and `hooks.properties_for_new_head`
  (review's) touch no database. The `MERGE` in `validate_write.py` is `replace_urls`, an update's. The writes of a
  create (`TOUCH_QUERY` on cited heads, `citations.record`, `check_bases`, `pending.mark_written`,
  `hooks.run_in_write`) all come after the statements, and are not run. `derived`'s citation resolver opens a read
  transaction of its own. All of it runs on Memgraph in a read transaction (tested); Neo4j not run here.
- **`@before_create` hooks are the project's** and are run (they are a refusal of the write): one may read the
  database (as the conformance's `label_is_new` does, through `search`); one that wrote would write here, as it does
  before a create. Said in the docstring.
- **What `checked_create` does not refuse that a create would**: what a create checks only after its statements: a
  citation of a part of the document itself that is not there or of a class its field does not take
  (`citations.record`), cited bases given in the payload that are not what an app makes (`citations.check_bases`),
  what the apps run in the write (`hooks.in_write`: `pangloss-derived` refuses a derived document made by anyone but
  its worker), and a uniqueness constraint broken by another write at the same moment. Said in the docstring and in
  `implementation_docs/memgraph.md`.
