# Report: step 7a.3, built by `builder` (2026-11-21)

Choices made while building, written as they were made. Not committed.

## Choices

1. **Where the rule is.** `meta.model_included(model, settings=None)` holds the rule of the brief's point 2, in its
   order; `meta.included(type_name)` is it by name (a name that is no model's: yes, as before). A class "declares"
   `_vectors_meta` when `getattr(model, "_vectors_meta")` is a `VectorsMeta`: the meta slots give every class the
   slot, `None` where nothing in its MRO sets it, so the nearest in the MRO is what `getattr` gives.
2. **Which stand-ins count.** `meta.stand_in_documents()`: the classes `hooks.stand_ins` name that are registered,
   are `Document` subclasses and are not generic wrappers (`is_generic_stand_in`, imported inside the function from
   `pangloss_models.initialise_models.initialise_field_definitions`, so that importing `meta` imports no more than
   before). Review registers its stand-in whenever `pangloss_review` is imported, installed or not; it only counts
   once a class `Unreconciled` is declared, which is when its models are loaded.
3. **The settings.** `settings.vectors_exclude()` and `settings.vectors_include()` read them (default none). A list
   or a tuple of strings; anything else (a bare string, a set, a list with a number) is refused naming the setting.
   They are checked at `initialise()` by `meta.check_settings`, called from `check_profiles` (so only when the app
   is installed, after the installed apps are imported, which is what lets `VECTORS_INCLUDE = ["Unreconciled"]`
   find review's class). Refused: a name that is no model's; a name that is not a class of documents or entities;
   a name in both. `VECTORS_INCLUDE` naming a class that is no stand-in is allowed (it changes nothing).
4. **What is "excluded", for the signature.** `meta.excluded()`: every registered class of documents or entities for
   which `model_included` is false, whatever says so (`VECTORS_EXCLUDE`, a stand-in, or `VectorsMeta(include=False)`).
   So a project that already has a class with `VectorsMeta(include=False)` gets one rebuild due after this change
   (its stored signatures were made without the list). That is the brief's rule as written ("the names of the
   excluded classes"), and it mends the same fault for `VectorsMeta`: changing `include` on a class made no rebuild
   due before. A project with nothing excluded keeps its stored signatures (tested).
5. **The signature function** is `store.part_signature(part)`, in `store.py` (where `profile_signature` is, and
   `store` already imports `meta`). Used in `rebuild.py` (stored), `status.py` (compared and shown),
   `store.profile_signature`, `pangloss vectors weights` (shown, so that its figure is the one the status shows),
   and the tests' helper `vectors_live_support.write_and_combine`. The status's reason keeps its text, with "or which
   classes have no vectors" added to what may have changed.
6. **Where the route leaves an excluded hit out**: in `nearest`, in the query itself (`AND NOT item.type IN
   $excluded`, the list `meta.excluded()`), so that the growing fetch still fills `k` with hits that may be shown
   and every caller of `nearest` (not only the route) is covered. `item.type` (the item's class now), not the
   vector node's `type`. The clause is only in the query when something is excluded
   (`search_query(index, excluding=bool(...))`): with it always there, `pangloss-fastrp`'s
   `test_fastrp_nested_live.py::test_the_class_part_s_queries_and_the_search_read_from_indexes`, which runs
   `search_query(index)` with its own parameters, failed for want of `$excluded`, and that package is not to be
   touched. So a project with nothing excluded runs the query it always has. Not measured: the plan of the query
   with the clause (a filter on a property of a node already matched by id, after the index; it should add no scan,
   but no `PROFILE` was read).
7. **Cost of the rule in the store.** `_rows` and `_write_combined` ask `meta.included` once for each class in the
   page (`store._included`), not once for each row: the rule reads the settings and walks the MRO.
8. **`pending_work_of`** marks every head that is a document or an entity when the app is installed (brief point 5).
   The live test that said a class with `include=False` is not marked now says the opposite, and that after one
   turn of the worker it has no vector.
9. **The status's reason** keeps its first words ("its signature is now X, not the Y it was built with:") and says
   "the models it reads, a setting it depends on, or which classes have no vectors changed". The one existing test
   that matched the old ending (`test_a_changed_class_decay_says_a_rebuild_is_due_and_a_rebuild_clears_it`) now
   matches "a setting it depends on".
10. **Live models with a stand-in**: `vectors_live_support.declare_hearings()` (a `Witness` with
    `ReviewMeta(allow_unreconciled=True)`, a `Hearing` of `Testimony`s given by witnesses, a `Note` about a witness),
    with `pangloss_review` put in `INSTALLED_APPS` by the test, as the e2e project has them. `similar_models` was not
    used: its `Person` does not allow an unreconciled. "Every part" in the live tests is the class part and a test
    part (`WaitingPart("other")`) given a row for every document and entity; the graph part is not in this package's
    tests (it is `pangloss-fastrp`'s, and that package was not to be touched).
11. **e2e**: the hearings are made by the author and published by the admin, so that the graph sees them (a hearing is
    reviewed and `VECTORS_GRAPH_SEES` is `everyone`). Unpublished, the mention was not among the hearing's similar
    even with the rule switched off, so the test did not bite; published, with the rule switched off by hand (a
    temporary edit, put back), it fails on the mention in the results. It checks the API's answer (no result is an
    `Unreconciled`, nor either mention's id) and the page (no `/Unreconciled/` chip, the other hearing's chip there).
