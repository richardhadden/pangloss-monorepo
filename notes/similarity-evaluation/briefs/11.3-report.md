# Report: step 11.3, an event: a stand-in was resolved

Written as the work goes (builder, 2026-11-23).

## Choices

- Names as briefed: `hooks.Resolution`, `hooks.resolved`, `hooks.tell_resolved`. Nothing in `hooks.py` clashed.
- `stand_in_type` for review is `meta.STAND_IN.document` (`"Unreconciled"`): the mention's row does not hold the
  node's `type`, and the query that reads it matches the label `Unreconciled` only. No query more, and no field more in
  the row.
- `stood_for` for review is `row[STAND_IN.named_type]` (`unreconciled_type`), read through the stand-in's
  `named_type` rather than by the literal name.
- The user is `pangloss_users.current_request_username.get()` at the moment after the write: the same context
  variable the write records as `updated_by` (in the background tasks too, which copy the request's context).
  Imported inside the function, as `pangloss_review.meta` does.
- Criteria: `replaced_where` is unchanged. The function `reference` that it calls for each place it replaces now
  records the part's id and `type` (the node's type as the read gives it: `MatchesCriteria`), so the places are known
  with no change to its signature.
- Review: one helper `_tell_resolved(row, model, entity_id, direct)` in `reconcile.py`, called after
  `_reconcile_one` in `reconcile` (not `in_form`) and in both `reconcile_other` closures (in `reconcile` and in
  `reconcile_with`), each time before `give_uris`. The code made the order easy: the URIs come after the write
  everywhere.
- `entity_id` in review is the id of the entity as read (`entity.id`, which may differ from the one given if it was
  named by a URL); in criteria it is the entity as given (`entity.id`, `entity.type` of the `Reference`): a merged
  entity is written as its survivor by the update, but the event names what was asked for. No query more to know
  better.
- `at` is `datetime.datetime.now(datetime.UTC)` after the write; in criteria one `at` and one user for every place of
  a resolve.
- Pure tests: `packages/pangloss-models/tests/test_resolved_hook.py`. Conformance: a new file,
  `conformance/test_resolved_live.py` (it imports `models`, `factoid`, `mention` of `test_reconcile_live.py`);
  `reconcile_with` is called directly. The listener that writes makes a node `PGResolvedForTest` through
  `backend.current().database().write_transaction`. Criteria: three tests at the end of
  `test_criteria_resolve_live.py`.
- Docs: `implementation_docs/models.md` (a paragraph "A stand-in resolved", after `named_type`: the hooks of stand-ins
  are documented there, not in `meta-slots.md`), `review.md` (a bullet among the notes on reconciling),
  `matches-criteria.md` (a bullet under the API's differences), the skill's `references/architecture.md` (the list of
  hooks).
