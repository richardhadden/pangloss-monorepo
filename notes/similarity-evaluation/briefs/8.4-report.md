## Choices, as made

- **How a package calls it: a base class.** `pangloss_testing.parts.PartSuite`; a part's test module subclasses it
  (`class TestTheGraphPart(PartSuite)`), names its parts with their slow ways in `parts = {"graph": slow, ...}`, and
  gets every claim as a test of its own. Not a function that makes tests: pytest collects an inherited class's
  parametrised methods with no more said, and a subclass can add claims of its own through one hook (`also`, below).
  The base is not collected where it is defined or imported (its name does not begin with `Test`), and its module is
  not named `test_*`, so `pytest packages/pangloss-testing` does not collect it either.
- **The installed apps and settings come from the conftest, not the module.** `installed_apps` and `settings_extras`
  are session fixtures that `initialise_settings` is made from once; a test module that overrode them would get the
  settings another module made first. So `pangloss_testing.parts` gives `installed_apps(*more)` and
  `settings_extras(**more)`, which a part's `tests/live/conftest.py` returns.
- **Several parts in one suite.** `parts` is a mapping of part names to slow ways, all checked after every step, so
  the graph part's module checks the class part beside it as it did (one set of writes, not two).
- **A hook for what one part alone asserts**: `async def also(self, step, m, ids, database)`, called after the
  suite's own check of each step, by the step's name (`"after a create"`, `"undeleted"`, `"unmerged"`,
  `"saved unpublished"`, ...). The graph module puts there what it asserted before that does not hold for every part
  (Eve has a graph vector again after the undo; the secret factoid is in the graph only while published under
  `"everyone"`; the activity has a class vector again after the undelete).
- **Tolerances by part.** `tolerance` (10⁻⁵) for every part, `tolerances = {"class": 1e-8}` for one. The graph
  module's class part was compared before with `np.allclose` (1e-8 + 1e-5·|b|); 10⁻⁵ absolute would have been
  looser, so it is 1e-8 absolute (stricter than before for values above 0.001; it passes).
- **"Nothing gone keeps a vector" is said outright**, not only through the slow way's ids: `writes.GONE` names what
  each write takes away (the old activity of the update that drops, the old `Fay child` of the replacing update — the
  graph module's own test of that before — and the meeting and activity of a delete), and the deleted meeting and
  activity, and the absorbed Eve, are checked to have no `PGVector`/`PGProfileVector` of any part or profile.
  This covers the graph module's old `Eve not in stored`, `Eve not in class_vectors`, `activity not in class_vectors`.
- **Publish under both values**: before, only `"everyone"` was tested. Under `"logged_in"` the graph module's `also`
  asserts the secret factoid is in the graph at every step (new, the graph part's own).
- **The overlay claim** has two payloads: the factoid of `test_fastrp_part_live.py`'s overlay test (a nested
  activity with an `InRole` with a place, a `Sworn`, an inference citing), and a person (`Hal`), for a part that
  gives documents no vector (names). Claims: the node count is unchanged by the overlay; what it gives is a subset of
  what is stored after the same instance is written (`write_head_node`, which marks it as a save does) and one turn,
  equal to the tolerance; the head is in the overlay iff it is stored. Seen in a scratch run: the graph part gives no
  vector to the lone person and its overlay none; the class part gives both.
- **The rebuild under writes is slowed generically**: the last registered part in name order (the last a rebuild
  builds, so every part before it has read and written) has its `rebuild` wrapped on its type: it runs whole into a
  list, the test is told, it waits for `go`, then writes the list. For the graph module the last part is `graph`, as
  before (it read the graph whole, waited, then computed: now it reads and computes, then waits; either way all it
  read is before the writes). The writes meanwhile are the old five plus the new rename.
- **The new write**: `update_that_renames_a_person` (Ada to "Ada of York"), in `WRITES` and in the rebuild under
  writes. For the graph and class parts a rename changes no vector: a scratch run with every part's `refresh` made to
  do nothing failed every claim (14 tests) except this write's, as expected; it is there for the name part.
- **The class part through the suite** fits: `packages/pangloss-vectors/tests/live/suite/` (a conftest of its own,
  since the apps are session fixtures and that package's other live tests install `pangloss_vectors` alone) and
  `test_vectors_class_part_suite_live.py`, `parts = {"class": class_rebuild}`, tolerance 1e-8. It needed
  `pangloss-derived`, `-library`, `-criteria`, `-review` as dev dependencies of `pangloss-vectors` (as `pangloss-fastrp`
  has them): `pyproject.toml` and 8 lines of `uv.lock` (`uv sync --all-packages --all-groups --all-extras`).
- **What stayed in the graph module as its own**: the criteria worker's new candidate joined (it reads
  `maths.joins`), the two tests past the cap, the batch in groups. `class_vectors`, `class_rebuild`, `as_a_rebuild`,
  `built` stay there for them.
- `fastrp_live_support.py` imports `NAMES`, `ref`, `alternatives`, `transfer`, `meeting`, `described`,
  `write_shapes`, `differences`, `drop_vector_indexes` from `pangloss_testing.parts` (with `# noqa: F401`), so its
  other tests are untouched. `differences` now says "the slow way" where it said "the oracle" in its messages.
- The fastrp conftest's `installed_apps`/`settings_extras` now come from `parts.installed_apps("pangloss_fastrp")`
  and `parts.settings_extras(FASTRP_REFRESH_CAP=...)`: the same values as before.
