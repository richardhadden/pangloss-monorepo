# Step 10.5a': the builder's choices, as made

1. **The interface confirms through the form, not the route.** Its Confirm replaces the part in the form, and the
   part is saved with the document. So "Confirm as this one" in the interface works the same way: the target is
   collapsed to that entity (`confirming.ts` `confirmedAsOne` = `confirmedPart` over `targetOfOne`, which the module
   already had), and the others ticked are given that target (`giveIdentification` with the entity). The route's
   `entity` is for API callers. **So a person's confirmation in the interface reaches `hooks.confirmed` through the
   save (`on_write`, `direct=False`), never as `direct=True`.** 10.5f must know this: row 4 wants a person's Confirm
   to be the event to learn from, and in the interface that event is never `direct`.
2. **The dialog now opens for every suggestion with several candidates.** Before, it opened only when there was
   something to ask (URIs for one candidate, similar suggestions, mentions, strangers). Without this, "Confirm as this
   one" could not be seen for a suggestion with nothing else to ask ("no action that cannot be seen"). Three existing
   e2e tests confirmed such a suggestion in one click (`test_what_a_toolchain_made_…` ("Not alike"),
   `test_a_projects_own_kind_…`, `test_an_identification_confirmed_with_several_candidates_keeps_the_uris`). They now
   press Confirm in the dialog. **This changes how the button behaves: the caller or the user should confirm it.**
3. **The event's user after a save** is `writer()`, noted with the confirmation: the first person a write names, or
   else the request's user (`ConfirmedInWrite.by`, falling back to `event.user`). That is the identification's
   `identified_by` for an admin's upload in someone's name. **The toolchain check reads `event.user`**, the user of
   the write, as the brief says.
4. **`ConfirmedInWrite`** gains `was` (the class of the suggestion it was; `None` for an identification that only
   keeps URIs), `type` (the class written) and `by`. "Was a suggestion" is worked out from `previous.type` through
   the registry, not from the view's class.
5. **A refused write leaves its note behind** (seen: the version check comes after `@before_update`, so a refused
   save leaves `confirmed_in_write` set in the context). `on_write` now takes only those noted entries whose
   `(id, type)` is among the nodes of the write's payload (`nodes_of(event.payload)`), and the background still checks
   that the node is no longer a suggestion. Test: `test_a_save_that_fails_is_told_nothing_even_after_another_save`.
6. **One read for a save's entities**: `graph.candidates([id])`, read once and given to both the event and
   `_give_uris_to_the_one` (it takes the candidates it was given, `held=`).
7. **The route's paths** (`confirm`, each `also`, `give_to_others`, `confirm_as_entity`) take the entities from the
   target `_confirm_one` returned (`entities_of`, a new pure helper in `identify.py`; `several` now uses it). No
   query is added.
8. **`confirm(entity=)` with `also`**: each of the others is confirmed as that one entity too (`target_of_one` over
   its own target), not given the first one's collapsed target. This gives the same result, and is right for
   others of another shape.
9. **A confirm as an entity that is not there** is the 422 `PanglossReferenceError` of the write ("Invalid
   references to existing objects: alternatives: '…' not found"). Usable, so the entity is not checked first. An
   entity of a class the place does not take is the 422 `PanglossReconcileError` "Factoid One does not take that:
   …". Both are tested.
10. **The text in the interface**: `SourceText` in `where.tsx`, quoted by a `t()` slot (`review_suggestion_text`:
    “…”, „…“, « … »), placed first in `SuggestionWhere`, where a mention's label comes first in `MentionWhere`. That
    puts it in the list, the dialog, and the suggestions the reconcile dialog offers. Its test id is `source-text`,
    because the library's `SuggestionText` in the form already uses `suggestion-text`.
11. **The alternatives in the dialog**: a grid row for each candidate, made of its chip (`ReferenceChip`), its
    likelihood and a `buttonClass("quiet", "sm")` button with the tick and "Confirm as this one", whose accessible
    name is "Confirm as {label}". This follows the reconcile module's candidate rows. The help text above says that
    the URIs go to that one when it has URIs. Translations are in en, de and fr, the module's languages.
12. **Dev build**: `test_dev_mode.py::test_the_tasks_of_review` now uses an `IdentificationByToolchainFromText` with
    two alternatives. Its second witness is "Another witness": a name with "Dev" in it made the picker's "Dev
    witness" option ambiguous.
13. **Stubs**: `framework_stubs` rewrote `pangloss_library/models.pyi`. It now holds `ConfirmedInWrite`'s new fields
    and also the other builder's `suggestion_classes` / `_register_suggestion_classes`, which are in the code now. The
    demo's stubs are not affected: no model changed.
14. **Docs**: `review.md` (the route's row; three sections: told to `hooks.confirmed`, confirm as this one, the text;
    and "Not mended" for row 21); `models.md` "A suggestion confirmed" (the hooks page, beside "A stand-in
    resolved"); `guide/review/README.md` (the dialog, Confirm as this one, the text, the route's `entity`, the hook);
    `status.md` review row; `e2e/COVERAGE.md` (two new rows; the confirm row; the library's `SuggestionText` row from
    ⬜ to 🚧, since the form's text is now seen in a browser); the skill: `references/architecture.md` (the hooks
    list). SKILL.md's review row is one line and is not made incomplete by this. `check_skill.py`: fits.
