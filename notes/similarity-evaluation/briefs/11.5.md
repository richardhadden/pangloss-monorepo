## What main decided

- **Two models from the same examples**, both by `pangloss_learn.fit`:
  - the **ranking** model: one `Example` for each row kept in a decision (`group` the stand-in's id), `yes` for
    the row that is `taken`. Its features: each scored part's cosine by the part's name, and `shared` (the score
    as kept), in the order `sorted(parts) + ["shared"]` where `shared` is there only if its weight is above 0.
    Compared by `pangloss_learn.compare` against the hand-set score (`score.score(row scores, weights)`);
  - the **"none of these"** model: one `Example` for each decision, over the head of the **displayed** rows as
    ranked by the hand-set score: `best` (the best displayed row's score), `gap` (to the next displayed row's
    score; with one row, `best` itself), the best row's own features under the names `best_PART` and
    `best_shared`, and `rows` (how many were displayed, as `log(1 + n)`). `yes` when none of those displayed was
    taken (`taken` is null, or names a row not displayed). A decision with no row displayed is **left out,
    counted** (no figure for an empty list). Compared by `pangloss_learn.compare_calls` (against always answering
    the commoner).
  One pure module, `learning.py` (no database in it): `ranking_examples(...)`, `head_features(rows) -> dict |
  None` (None for an empty list; **step 11.6 calls this same function on a live answer**, so it takes rows as
  plain data: score, scores, displayed), `none_examples(...)`, and the feature lists.
- **Which examples**: only those whose `profile`, `signature`, `parts`, `weights` and `features` are **today's**
  (`RECONCILE_PROFILE`; the signature of the profile's vectors in use and its parts', as `decisions.py` stores
  them at a request; `settings.weights()`; `decisions.FEATURES`). The others are left out and counted ("of other
  vectors or weights"). Then those in which a row lacks a part the features need (the unknown had no vector of
  it: fault 11) are left out and counted. One function says what "today's" is, used by 11.4's writer, by this
  step and by 11.6: if 11.4 did not make it one function, make it so.
- **`PGReconcileModel`**, a plain node, one for each fit that is written, **none ever deleted**: `id` (a UUID),
  `at`, `profile`, `signature`, `parts`, `weights`, `features` (as an example has them), `decisions` (how many
  went into the fit), `latest` (the newest example's `at`), `ranking` and `none` (each a `Model.to_json()`, or
  null when it could not be fitted, with `ranking_why` / `none_why` the `Unfittable`'s message), `compared` (JSON:
  for each of the two, `decisions`, `model`, `baseline`, or null), `in_use` (bool; **at most one node true**, set
  and unset in one write transaction). `structure.py` and a migration `0002` (unique `id`).
- **The check (call e)**: a fit is put in use only when (1) its decisions are `RECONCILE_LEARN_FROM` or more
  (a new setting, a whole number of 1 or more, default 100, checked at `initialise()`), (2) its "none of these"
  model was fitted and `compare_calls` found it no worse than the commoner answer. The ranking model's comparison
  is **recorded and used by nothing yet** (step 11.6 decides whether the ranking is ever by the model; the trial
  says not): a ranking model that is worse, or could not be fitted, does not keep the fit out of use. A fit that
  fails the check is still written, not in use, and the earlier one in use **stays in use**; the command says
  which condition failed.
- **`pangloss reconcile learn`** (`cli.py`, beside `sweep`):
  1. `decisions.sweep()`;
  2. read the examples; leave out and count as above;
  3. if the newest `PGReconcileModel` of today's signatures has the same `decisions` and `latest`: write
     nothing and say "nothing new since the fit of DATE";
  4. fit both, compare both (`folds=5`, `seed=0`, the ridge 1.0), write the node, put it in use or not;
  5. print, in plain lines: how many swept; examples read; left out by each reason; decisions; for each model,
     fitted or why not, and the comparison ("the one taken was first in 81 of 100 by the model, 84 by the score
     set by hand"); what was written (its id) and whether it is in use, or why not.
  `--dry-run`: all of it but nothing written (the sweep included: it says how many **would** be swept, if that
  is cheap; otherwise it does not sweep and says so). `--use ID`: no fit; puts an earlier fit in use **through
  the same check** (its stored `decisions` and comparison, and its signatures must be today's), refused with
  the reason otherwise. `--use none`: no fit in use (back to no model). A function `learning`/`models` API in
  Python does the work (`learn(dry_run=False) -> Learnt`, `use(id | None)`); the command only prints.
- **An admin job** (`admin.py`): `reconcile_learn`, with a choice `dry_run` (`no`/`yes`); its counts as the
  job's progress counts, the printed lines as a report file in the job's directory. `pangloss-admin` is not a
  dependency: the module is found by it, as `pangloss-vectors`' is.
- `pangloss-reconcile` now depends on `pangloss-learn` (`pyproject.toml`; then
  `uv sync --all-packages --all-groups --all-extras`, never a plain `uv sync`; do not stash or check out

## Tests

- Pure (`tests/test_reconcile_learning.py`): the ranking examples of hand-made kept rows (the features' order;
  `yes` on the taken row; none `yes` when `taken` is null); `head_features` for no row (None), one row (`gap`
  is `best`), several (by the hand-set order, displayed rows only); the "none" example's `yes` for `taken` null,
  for a row taken that was not displayed, for a displayed row taken; rows lacking a part are told apart.
- Live (`tests/live/test_reconcile_learn_live.py`, both backends). Examples are written directly (a helper that
  writes `PGReconcileExample` nodes of made-up rows through `decisions.py`'s own writer, with today's
  signatures; a seeded generator in which the taken row has the best name and "none" lists have a low best
  score, so that both models can be fitted and are no worse): no examples (says so, writes nothing); fewer than
  `RECONCILE_LEARN_FROM` (written, not in use, says why); enough (in use; exactly one in use); a second run
  with nothing new (writes nothing); more examples then a third run (a second node; the newer in use, the older
  kept and not in use); a model worse than the commoner answer (the "none" answers drawn at random against the
  features) is written and **not** put in use, and the one in use before stays; examples of another signature,
  of other weights and of another `features` number are left out and counted; `--use` of the earlier fit;
  `--use` of a fit whose signature is not today's refused; `--use none`; `--dry-run` writes nothing and removes
  nothing; every example "yes" or every one "no" for the "none" model (it is null, with why, and the fit is
  not in use); the command through the CLI runner (as `pangloss-vectors`' CLI tests do) printing the lines; the
  admin job (as `pangloss-vectors` tests its job, if it does: follow that; if it has no test, a test that the
  job function runs with a made-up context). The CLI guide and its test.
- Each new setting's refusal by its message (`test_reconcile_settings.py`).
