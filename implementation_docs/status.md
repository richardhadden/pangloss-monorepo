| 🚧 | **Label templates** ([label templates](label-templates.md)): `Meta(label_template=...)` works a label out from what an item holds, nested documents first, in Python on every write and in the form as it is filled in (locked, a pencil to write it by hand); `label_auto`; `Formatter`s (a date) | Not measured on a large database; formatters only in English; the demo has no templates; see the page's "As built" |
| ✅ | **Companion documents** ([companion documents](companion-documents.md)): `Entity.Meta(companions=...)`: documents offered with a new entity in the dialog that makes it and on its own page, copying from the document behind, with the entity in each part; written with it in one transaction (`create_heads`, `POST /api/NAME/with-companions`, `save_with_companions`) if anything in them is filled in | Parts through wrappers; companions of a document made in a dialog; a text of each companion's own; offered for an existing entity |
| ✅ | **Generated models** ([generated models](generated-models.md)): `Create`, `Update`, `View`, `HeadView`, `EditView`, `ReferenceSet`, `ReferenceView`, the database models, `Where` and `Order`; validators once, `@create_validator`, `@before_create`, methods | |
| 🚧 | **What the server computes** ([matches criteria](matches-criteria.md), "`Computed()`" and "As built"): `Annotated[..., Computed()]` on a relation or a literal: read with its model, in no `Create` or `Update`; written by `operations.set_computed` alone, with a check of the head's version and no new version; kept by an update for a node that says the same; no reference (deletion, usage, merges) | |
| 🚧 | **Matches criteria** ([matches criteria](matches-criteria.md), "As built"): someone described and not named, as a stored search linked to everyone it fits. Built: `Computed()` (above), a search that leaves wrappers out (`exclude_wrappers`), and in `pangloss-criteria` the literal type `SearchPattern`, the class `MatchesCriteria[T]`, written in a field's annotation or offered wherever an entity of a class with `CriteriaMeta(allowed=True)` goes (a generic stand-in; `NoCriteria()` on a field opts out), the mark a save leaves, and a worker that evaluates the descriptions of each saved document (the cap, not what the document names, two results by who may see) and those of other documents that a write could change (every write of a class the criteria could reach is marked; an update's mark keeps what the document named and was before; a description is evaluated among the entities a batch of writes names, or in full from an entity its criteria name, many of one shape in one query; `pangloss criteria status`, `explain`, `rebuild`, `check`). With `pangloss-derived`: a rule reads through a description (`qualify`, one candidate for each justification, only the candidates everyone sees), a document rule only with `allow=[MatchesCriteria]`, and criteria do not read a document derived through a description (`search.head_conditions`); `idle()` waits for both workers. The interface (an interface module of `pangloss-criteria`): a dialog with the search form and a preview, the card in a form and in a view (candidates, "Finding candidates…" until the result arrives), "This is…" to put an entity in its place, "identified as candidate" on a candidate's page; routes `/api/criteria/preview`, `/{id}/candidates`, `/{id}/resolve`. The same one in several places of a document: a shared mark, `same_one` (one place holds the criteria, every place gets the candidates, a rule takes one candidate for all of them, "This is…" fills all); identical criteria in a batch are evaluated once. Migrations: each change of a migration rewrites the stored criteria in its transaction (`hooks.migration_changes`, `migrations.patterns`), what it cannot rewrite is broken (`broken`, `broken_since`; listed at `/criteria/broken` and by `pangloss criteria check`), and after `migrate` every description is checked again (`hooks.after_migrate`); history upgrades the patterns of old versions (`LiteralCodec.migrate`). Shared descriptions: a `Description` (a document with a label and criteria) that a mention cites (`description`), with conditions of its own; edited in one place, every mention evaluated again; "Start from", Use and Copy, and the offer to share identical criteria (`/api/criteria/shared`, `similar`, `share`) | Conditions relative to the document: steps 12 to 14 of the plan. A description cannot be copied in a form. Not measured on Neo4j at scale |
| ✅ | **What a mistake in the models says** ([modelling DX](modelling-dx.md), [language server](language-server.md)): `PanglossModelError` naming model, field and fix; `pangloss check`; `pangloss-lsp` with its Zed extension | The VS Code extension compiles and has not been run |
| ✅ | **Storage** ([database abstraction](database-abstraction.md), [Memgraph](memgraph.md), [Neo4j](neo4j-implementation.md)): one implementation for Cypher databases (`pangloss-cypher`) with a dialect each; one conformance suite both pass; create, replace-on-update with a version check, flag-delete and undelete, reads, lists; accents folded in search on both; a vector search as a named point of the dialect (`Dialect.vector_search`) and, on Memgraph, a query module installed from Python (`backend.install_query_module`): hooks; `pangloss-vectors` uses the first, nothing yet the second | A backend that is not Cypher ([RDF report](rdf-oxigraph-feasibility.md)); removing deleted nodes for good |
| ✅ | **Bulk load** ([large data](large-data.md)): a JSON Lines file into an empty database, on either backend | Only entities with ids of their own can be referred to from a file |
| 🚧 | **Migrations** ([migrations](migrations.md)): `makemigrations`, `migrate` (forwards, backwards, dry run, batches, backup), `squashmigrations`, `check-data`; the API does not start with migrations pending; a vector index as a kind of index (`AddIndex` with `kind: "vector"`), on both backends | See its "Progress" |
| ✅ | **Search**: lists with text and [deep search](deep-search.md); [autocomplete](autocomplete.md); [structured search](structured-search.md) by a JSON pattern, typed in Python as [`Model.Where`](search-where-implementation.md); "search everything". The way of a relation through wrappers and edge models: `through`, `edge`, `exclude_wrappers`, a wrapper's own relations by id, and `via` (the places of the way in order, on an edge or a node, also in `$incoming`; [plan](relation-steps-plan.md), "As built"); an edge says which edge model it is of, so two alike are told apart | Deep search is still slow on a large database (a scan of the text index); `via` is not in the search form nor in a derived rule's body |
| ✅ | **REST API** ([API](api.md)): CRUD for every document and entity, `If-Match` on updates, login by token or cookie, sessions that end, personal access tokens, CORS; routes and background tasks from installed apps | |

## Measured

On about 640,000 nodes: [large data](large-data.md), [the two backends compared](backend-comparison.md),
[profiled](backend-profiling.md), [derived relations](derived.md#measured),
[structured search](structured-search.md), and merging, citations and clusters of identity
([duplicate entities](entity-identity.md), "Measured after building": 590,000 nodes on Memgraph, 25,000 on Neo4j), and
similarity ([vectors](vectors.md#measured), [FastRP](fastrp.md#measured): about a million nodes, Memgraph only;
[names](names.md#measured): a planted world of 302,239 nodes of the models, the base on both backends;
[the time part](dates-vectors.md#measured): a dated planted world of 856,790 nodes, on both backends).
